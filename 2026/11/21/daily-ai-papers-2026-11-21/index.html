局部意图让机器人动作可以逐步核查

论文：AgentRoboCritic: Understanding the Capability of Frontier Agents on Direct Robot Control（arXiv:2611.26613）
作者：Yiyang Du、Yuxuan Kuang、Qitao Zhao、Yixuan Wang、Zhanqiu Guo、Yi Xu、Xin Li、Wenbin He、Liu Ren、Chenyan Xiong
来源/分类：arXiv · cs.RO（cs.RO, cs.CL, cs.CV）
原文：PDF · 代码
全文状态：已核阅 arXiv 官方 HTML 全文或 PDF；以下结论为作者报告，尚无独立复现。

  • 核心问题、方法与基线：常见机器人评测只报告整段任务成功率，无法解释具体失败。作者让策略模型为每个低层动作附上局部意图，再由多模态 critic 根据任务目标、意图和动作前后多视角图像判断成败与失败类型；分析覆盖 12 个操作基准。评测同时比较 GPT-6 Astra 与专用 VLA/WAM 基线，并在 400 个经人工标注动作上检验 critic。
  • 作者报告的关键结果：跨基准中，38.9% 的失败动作在之后 10 个动作内被修复，57.7% 在回合结束前得到恢复。动作级数据集含 12,844 条标注；Muse-Glimmer-30B 的失败模式准确率从零样本的 32.58% 升至微调后的 74.24%。74 个匹配任务中，GPT-6 Astra 的决策中位延迟为 31.9 秒，专用策略 π0.5 为 0.11 秒。
  • 创新与证据边界：局部意图让动作判断有明确参照，人工小样本验证也检查了自动 critic；论文还测了同一前沿模型兼任策略与 critic 的自偏差。但核心策略依赖闭源模型，模型版本、API 与成本会影响复现；400 个动作的人类集较小，12 个基准的成功率不能直接外推到真实生产任务，且 31.9 秒延迟显示其闭环速度有明显限制。全文未见对公开机器人基准训练污染的专项审计。作者报告结果，尚无独立复现。
  • 适合谁读、建议章节：适合机器人策略、具身 agent、动作级评测和安全监控读者。建议读 §3.2 的意图条件 critic、§4.1–4.3 的能力与失败、§5 的人工验证，再看附录 H.4 的延迟与附录 I 的自偏差检查。

直接修改权重能否修复小型视觉语言模型的循环推理？

论文：Keel: A Frontier Model Teaches a Vision-Language Model by Rewriting Its Weights（arXiv:2611.25257）
作者：Jiajun Fan、Neil He、Bangji Yang、Qinglong Zheng、Ziwen Wang、Chaoran Cheng、Changyi Yang、Hanqi Mao、Ge Liu
来源/分类：arXiv · cs.CV（cs.CV, cs.AI）
原文：PDF
全文状态：已核阅 arXiv 官方 HTML 全文或 PDF；以下结论为作者报告，尚无独立复现。

  • 核心问题、方法与基线：Qwen3.5 小模型在视觉问题的思考模式中会反复循环，耗尽 token 预算。Keel 让前沿多模态模型在只知道症状的条件下检查失败案例、定位权重方向并提出编辑；编辑需通过失误比例下降且留出题准确率不降的筛选。作者在 Qwen3.5-0.8B/2B 的六个视觉基准上，对比原始思考模式、presence penalty、reflection suppression、budget forcing 和既有权重编辑。
  • 作者报告的关键结果：六项任务平均准确率中，0.8B 从思考模式的 48.2% 升至 Keel 的 56.1%（+7.9 个百分点）；2B 从 65.2% 升至 72.3%（+7.1 个百分点）。两模型输出中以逐字循环结束的答案比例，平均分别下降 21.8 和 12.4 个百分点；2B 在 GUI grounding 上的提升尤其大，该任务未进入编辑练习题。
  • 创新与证据边界：它把修复直接写入模型权重，再与解码时 budget forcing 组合；作者的注意力诊断指向中间层注意力输出。比较含多种推理时基线，且以留出题筛除只会损害准确率的编辑。限制是只测两个 Qwen 小模型和六个既有基准；文本未报告明确的预训练污染审计。每个模型需 3–4 轮前沿编辑器、每轮数小时并占用 GPU，部署推理虽不增单 token 成本，但编辑成本不低。
  • 适合谁读、建议章节：适合模型编辑、视觉推理和推理成本优化读者。建议读 §2 的失败盘点与筛选目标、§3.1–3.2 的基线和结果、附录 C.2–C.9 的数据/统计/资源设置及附录 D.2。

图像编辑安全评测暴露文本与视觉判断错位

论文：Text-Aware, Vision-Blind: How Multimodal Image Editing Systems Handle Unsafe Inputs（arXiv:2611.26569）
作者：Ziqing Yang、Yixin Wu、Michael Backes、Yang Zhang
来源/分类：arXiv · cs.CR（cs.CR, cs.CV, cs.LG）
原文：PDF
全文状态：已核阅 arXiv 官方 HTML 全文或 PDF；以下结论为作者报告，尚无独立复现。

  • 核心问题、方法与基线：编辑请求是否安全，取决于输入图像和文字意图两部分。EditSafetyBench 将 660 张安全/不安全图像与九类通用编辑指令配对，共 5,940 对，覆盖 11 个风险类别和中性、降低风险、危险意图三种指令；同一提示在安全与不安全图像上保持一致。作者比较 Gemini、GPT、Qwen API 与 Qwen 本地版的系统级允许/拒绝/错误决策。
  • 作者报告的关键结果：Gemini 与 GPT 对危险编辑意图分别拒绝 87.1% 和 81.6%，但面对不安全图像加中性指令时只拒绝 24.2% 和 22.4%。政治内容的危险编辑允许率也有差异：GPT 为 70.4%，Gemini 为 34.8%。这些比例衡量系统决策，不是生成图像最终有害程度。
  • 创新与证据边界：相同提示配安全与风险图像，能较干净地检验系统是否读取视觉风险；四个系统提供一定横向比较。但论文只评估允许/拒绝，不审核输出图像伤害或编辑质量；九条提示不能覆盖对抗性绕过和全部真实请求。闭源 API 的版本变化也会影响复现，全文未见对测试图像与模型训练数据重叠的专项审计。结果是作者对指定系统和基准的评测，尚无独立复现。
  • 适合谁读、建议章节：适合多模态安全、图像编辑平台和红队评测读者。建议读 §3 的基准构造、§4.2–4.7 的决策/跨模态差异及消融，再读 §5 与 Limitations。

深度研究代理的搜索查询会拼出私有信息

论文：MosaicLeaks: Privacy Risks in Querying-in-the-Open for Deep Research Agents（arXiv:2605.30727）
作者：Alexander Gurung、Spandana Gella、Alexandre Drouin、Issam H. Laradji、Perouz Taslakian、Rafael Pardinas
来源/分类：arXiv · cs.CL（cs.CL）
原文：PDF · 数据集 · 代码
全文状态：已核阅 arXiv 官方 HTML 全文或 PDF；以下结论为作者报告，尚无独立复现。

  • 核心问题、方法与基线：代理将企业内部文档与公开网页交替检索时，单条看似无害的搜索词也可能被外部观察者拼成敏感信息。MosaicLeaks 用 1,001 个多跳任务连接私有企业文档与公开网页，令攻击者只观察代理的外部查询，并尝试推断研究意图、私有问题答案和可核验文档事实。论文评测六个开放模型，并比较普通隐私提示、只优化任务成功的强化学习与 PA-DR。
  • 作者报告的关键结果：Qwen3-4B-Instruct 基线严格链式成功率为 48.7%、隐私泄漏率为 34.0%；仅做任务导向强化学习后，成功率升至 59.3%，泄漏也升至 51.8%。加入对查询级和拼接泄漏都给密集反馈的 PA-DR 后，成功率为 58.1%，泄漏降至 6.5%。摘要还报告在其他开放模型和独立 judge 上有相同方向。
  • 创新与证据边界：把“任务做成了”与“外部查询暴露多少私有上下文”同时计分，比只检查最终答案更接近真实检索边界；代码与数据集公开链接见下。结果建立在三个企业上下文和合成/人工质检任务上，攻击者拥有完整查询日志这一压力设定偏强；代理场景目前集中在多跳问答，不代表所有长篇研究流程。摘要未量化训练算力。
  • 适合谁读、建议章节：适合企业 RAG、隐私保护、工具调用与 agent 强化学习读者。建议读 §3 的泄漏定义、§4 的任务设计、§5 的奖励、§6 的评测与 §8 的限制。

Agent 能否独立完成在线强化学习后训练？

论文：Agent^2 RL-Bench: Can LLM Agents Engineer Agentic RL Post-Training?（arXiv:2604.10547）
作者：Wanyi Chen、Xiao Yang、Xu Yang、Tianming Sha、Qizheng Li、Zhuo Wang、Bowen Xian、Fang Kong、Weiqing Liu、Jiang Bian
来源/分类：arXiv · cs.AI（cs.AI）
原文：PDF · 代码
全文状态：已核阅 arXiv 官方 HTML 全文或 PDF；以下结论为作者报告，尚无独立复现。

  • 核心问题、方法与基线：现有评测常检查模型会不会写训练脚本，却不要求它在环境中采集轨迹、更新模型并闭合在线 RL 循环。Agent² RL-Bench 设六个任务、三个难度层级，从规则奖励的监督训练、judge 奖励优化到需要真实交互的在线 RL；比较五类 agent 系统和六种驱动模型，按每次 12 小时预算运行，并记录代码、训练产物和提交轨迹。
  • 作者报告的关键结果：某个 RL 导向运行通过 SFT 热启动、GRPO 和在线 rollout，把 ALFWorld 分数从 4.85 提到 93.28；但 DeepSearchQA 仍难，多数成功路径依赖监督式训练，交互结果对 agent 栈差异明显。基准原始试验共计 1,404 H200 等效 GPU 小时、5.48B 驱动上下文 token。
  • 创新与证据边界：它要求 agent 完成工程闭环而非仅生成代码，且把训练过程留痕，能区分分数提高与真正使用在线 RL。数字亮点来自个别任务/运行，不代表普遍能力；消融中有单次运行，任务只有六类，系统配置和驱动模型仍有混杂，成本也高。代码见摘要链接。
  • 适合谁读、建议章节：适合 RL 工程、自动化研究和 agent 评测读者。建议读 §2 的任务协议、§3.2–3.4 的跨系统/行为结果、§5 的限制，以及附录 C 的复现和成本表。

来源/分类：arXiv · cs.AI（cs.AI）
原文：PDF · 代码
全文状态：已核阅 arXiv 官方 HTML 全文或 PDF；以下结论为作者报告，尚无独立复现。

  • 核心问题、方法与基线：agent 请求会因长上下文、多轮工具调用与随机路径而波动，合成压力测试容易低估真实部署需求。作者提出从 live benchmark 记录完整会话，再用 trace replay 做容量 sizing、预生产和回归检查；对照是重新实时运行同一任务，并以 vLLM 代码覆盖检查不同负载的互补性。案例把四个大型 MoE 模型部署到 llm-d。
  • 作者报告的关键结果：在 HWE-Bench 和 CyberGym 各 40 条会话中，trace replay 的输入 token P95 最大约为记录值的 1.18 倍，而实时重跑在 HWE-Bench 达 4.98 倍；这说明固定回放更稳定，不代表它总能代表真实到达流。四个 MoE 案例中，基于捕获负载测出的目标并发约只有最优值一半，吞吐约为公开 trace 负载下的 60%。
  • 创新与证据边界：把模型质量评测产出的真实轨迹直接用于服务容量测试，量化了重跑随机性。限制是覆盖分析只看 vLLM 的 Python 路径，不含编译的 CUDA/C++ 核心，执行覆盖不等于正确性；案例只涉及特定模型、硬件和服务栈。工具与 trace 数据按论文说明开放，复现需匹配环境。
  • 适合谁读、建议章节：适合推理平台、LLM serving、SRE 与容量规划读者。建议读 §2 的全生命周期流程、§4 的 trace replay、§7 的覆盖分析、§8 的 MoE 部署案例及附录 D.3 的限制。

When AI Analysts Disagree: Agentic Multiverse Analysis and the Robustness of Empirical Research（arXiv:2611.25198）
