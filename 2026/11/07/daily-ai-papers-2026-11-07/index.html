Multimodal-SEA: Benchmarking AI Agent Security under Multimodal Social Engineering Attacks（arXiv:2611.08281）

研究问题与设计。 论文研究个人智能体能否识别伪造图像、文件、网页和视频所支撑的多模态社会工程，并避免实际转账或泄露信息。作者以真实诈骗案例设计 152 个场景、608 个中英文任务，构建含 50 个模拟应用的交互环境；攻击者会根据智能体反应调整多轮话术与内容。攻击成败根据工具调用、环境状态变化和实际损失记录判定，而不是只由文本裁判打分。

作者报告的结果与基线。 七个多模态模型在 316 个中文、292 个英文任务上均出现攻击成功。论文摘要概括成功率为 7.1%–34.5%；主结果按语言分开报告时，中文为 8.9%–36.7%，英文为 5.1%–34.2%。去掉多模态内容的消融中，加入图像等内容后，验证覆盖率从 54.7% 升至 65.1%，攻击成功率也从 19.9% 升至 29.2%。对 GPT-5.6-Sol 加安全提示后，中文攻击成功率由 34.8% 降至 10.8%，但欺骗内容漏识率从 50.4% 升到 63.5%；Claude Opus 5 攻击成功率较低（7.1%），同时对 32.1% 的正常请求误拒。

创新与证据边界。 价值在于把“说自己会核验”与真实执行核验区分开，覆盖识别率、实际操作、损失和误拒等不同指标。比较是在作者提供的模拟应用和攻击生成器下进行；攻击者使用 DeepSeek-v4-Pro，图片/视频内容分别借助 Gemini 与 Kling 生成。结果不代表真实个人设备、真实资金或所有语言环境；模型版本和闭源接口也会变化。攻击成功率不等同于真实世界损失概率。

适合谁读。 做多模态智能体安全、工具权限设计和防诈骗产品的研究者与工程师。建议按第 2 节理解任务与环境、第 3 节看攻击生成器、第 4 节核对主表，随后读第 5 节消融及误拒分析。基准代码：M-SEABench。

Concertina: Embodying Manipulation and Cognition in One Diffusion Vision-Language Model（arXiv:2611.07513）

研究问题与方法。 论文质疑视觉语言动作模型把认知与动作拆成两个部件的常见做法，提出 Concertina：在同一扩散式视觉语言 Transformer 中，以连续潜在动作 token 表示每个控制时刻，按动作块生成轨迹，并直接用物理坐标监督共享主干。模型为 4.46B 参数，动作投影仅占 0.21%，没有独立动作生成器；作者对比的连续 VLA 中，专用动作专家约占 16.5%–35.1% 参数。

作者报告的结果与基线。 在常规 LIBERO 的 2,000 个回合中，平均成功率 98.15%，高于表列的 π0.5（97.5%）、X-VLA（98.1%）、Dream-VLA（97.2%）和 π0（94.2%）。在 10,030 个扰动任务的 LIBERO-Plus 上为 85.9%（8,615/10,030）；在 CALVIN ABC–D 的 1,000 条未见环境任务链上，平均完成链长 4.142，SR@1 为 98.6%。训练使用 80.2M 帧的混合数据；预训练与下游训练均使用 8 张 GPU。

创新与边界。 共享主干让动作梯度直接进入视觉语言模型，作者的 Action Interface Audit 还尝试定位轨迹时间耦合出现的层级。上述成绩来自标准机器人仿真基准，不是实体机器人部署结果。基线训练数据、训练流程和算力并非统一重跑；论文表注也提醒 EFFVLA 的 LIBERO-Plus 数字为套件级平均，与本论文的官方全量任务口径不完全相同，因此不宜把每个差值当成严格同条件胜出。实际延迟、硬件控制稳定性及跨机器人迁移仍需独立验证。

适合谁读。 机器人学习、VLA 架构与动作生成研究者。建议先读第 2–3 节架构，再读第 4.1–4.5 节结果和消融，最后读附录 B 的训练配方与推理配置。代码与模型：GitHub、Hugging Face。

FlyingDrones: A Dataset and Benchmark for Optical Flow Estimation from UAV motion（arXiv:2611.07705）

研究问题与方法。 远距离无人机目标只有少量像素且背景复杂，传统光流榜单未充分覆盖这一情况。FlyingDrones 用物理渲染生成带稠密光流真值和分割掩码的数据集，并提出按图像分辨率归一化的 EPE Norm。论文评测 16 个模型家族、88 个公开 checkpoint，在分运动幅度和目标尺寸的 999 对样本、三个分辨率上比较；另用 21 个真实无人机摄像头做无稠密真值的运动对齐验证。

作者报告的结果与基线。 所有模型家族都优于零光流基线；分辨率升至 1920×1080 时，global-matching、循环更新、Transformer 与短时序方法整体拉开差距。checkpoint 选择和训练课程造成的组内差异可与架构组间差异相当，部分分辨率下组内差异达到数倍。合成评测的排名与真实镜头上的目标运动定位只有中等相关（Spearman ρ=0.63，41 个 checkpoint），精确名次并不保持。再用 800 对 FlyingDrones 样本微调后，四种架构的真实镜头定位均改善；三种架构的留出合成目标区域误差下降 19%–37%，VideoFlow 的真实镜头 NSS_D 从 4.9 到 17.8。

创新与限制。 论文同时报告公开模型、多个 checkpoint、置信区间和真实镜头代理指标，指出排行榜不能脱离训练数据与部署分辨率解读。数据是合成渲染，难以覆盖大气扰动、传感器噪声、压缩和滚动快门；真实测试是静态相机、点标签，不是稠密真值或移动平台测试。公开 checkpoint 的训练课程不同，比较反映架构与训练数据的合成影响，不能单独归因于架构。作者报告主榜约耗 40–50 GPU 小时，微调约 5 GPU 小时。

适合谁读。 光流、无人机视觉和数据集迁移研究者。建议读第 3 节数据与指标、第 4–5 节主比较和限制，再读附录 B.7 的真实镜头与 B.9 的 800 对微调。数据集：Kaggle。

MCPHallu: Benchmarking Reasoning, Execution, and Memory Hallucinations in MCP Agents（arXiv:2611.07689）

研究问题与方法。 MCP 智能体能调用多个服务器，但常见基准只记任务完成率，难以定位错误来自推理、执行还是记忆。MCPHallu 构造 358 个带结构性失败触发条件的任务，覆盖五个能力域、36 个生产 MCP 服务器和四类失败；在隔离容器中以 ReAct 循环评测 14 个模型、8 家厂商，共 5,012 条轨迹。配置统一为 128k 上下文、每题最多 20 次工具调用。

作者报告的结果与基线。 模型平均分为 0.642/1，平均通过率 47.8%，最高模型 0.728；“目标不可达”最难，平均分 0.458、仅 23.2% 轨迹通过。不同失败子类的模型排名差异明显，因此单一总分会掩盖能力结构。主语义裁判为 GPT-4o；论文另报跨裁判和人工校验。

创新与局限。 任务把目标不可达、工具误用、分支坍塌、上下文遗忘等风险写进环境，并用工具结果和轨迹核验是否真的完成。它能测试“工具不具备能力时是否承认做不到”，这一点比只测成功任务更贴近真实部署。语义评分仍依赖裁判模型，尽管作者做了人工/跨裁判验证；36 个服务器中 16 个需要调用者自备凭证，第三方 API 可能改变，完全离线的录制回放还未完成。统一工具预算和 ReAct 提示也不等于所有产品的默认工作流。

适合谁读。 MCP 客户端、工具调用 Agent 与可靠性评测团队。建议优先读第 4 节任务评分、第 5 节实验和第 6 节失败分析，再看附录 H、J 的裁判验证与方法限制。代码：MCPHallu。

Terminal-style Mathematical Modeling Bench: The First Agentic and Verifiable Benchmark for Mathematical Modeling（arXiv:2611.08237）

研究问题与方法。 开放式数学建模答案常由 LLM 裁判打分，数值接近参考解也不保证满足物理约束。TB-MathModel 把 2023–2025 年 CUMCM 与 MCM 的 18 道真实赛题装入隔离终端，要求 Agent 输出结构化 JSON；分数以多份优秀论文为参照，并设程序化可行性门槛，再用 Lean 4 对 624 项整数/有理数约束义务做内核检查。无可行性证据的任务不会被默认为通过。

作者报告的结果与基线。 七种多模态模型/代码代理组合、每题三次运行中，GPT-6 Astra+Codex 的 O-Eval 为 64.58±2.93，Fable 5.1+Claude Code 为 63.11±1.33；DeepSeek V4.1 Flash+OpenCode 为 59.81±1.25，作者估算 18 题成本 2.54 美元，而前两者约 246–273 美元。每一分差异都不是稳健排序：单种子偏差最高约 2.9 个百分点，邻近模型不能据此认定显著胜负。

创新与边界。 可迁移价值是把可判定的数值范围、单位和内部一致性变成可执行、可审计的校验，不让语言评审独自决定“正确”。但 18 道公开竞赛题可能已进入模型训练语料，论文没有证明所有模型都未见过题目；形式化检查只能证明预先编码的约束，不能替代现实物理真值。竞赛题型和多模态终端也不能代表一般科研建模任务。

适合谁读。 评测 Agent 长程推理、数学建模和可验证输出的研究者。建议读第 3 节基准与验证、第 4 节评分和结果，再看“Limitations”及附录 G。代码：TB-MathModel。

Agent-R²: Scaling Agents for Realistic Productivity Work via Real-Source Data Synthesis（arXiv:2611.08219）

研究问题与方法。 真实办公任务需要读写不同格式的附件、沿工作流完成多步操作，并交付可核验文件；合成文件可能不够真实。Agent-R² 从职业任务种子和网页工作流证据出发，在 10,000 个候选中筛出 4,000 个带真实多格式附件和细粒度评分规则的任务，用 3,000 个做监督微调、1,000 个做基于评分规则的强化学习，两阶段任务不重叠。

作者报告的结果与基线。 4B 模型在 GDPval Pass@1 得分 51.0%，高于论文列出的 Qwen3-235B-A22B-Thinking-2507（48.0%）；OfficeQA 为 14.8% 对 13.8%。在 1,000 个匹配任务的消融里，真实附件训练为 43.3%，模型自行合成附件为 41.4%；加入细粒度评分奖励后 GDPval 从 49.5% 到 51.0%。作者的附件哈希/来源 URL 检查未发现训练附件与 GDPval、OfficeQA 的文件重合。

公平性、复现与边界。 比较包含闭源与开源模型，但多模态文件工具、代理框架和评分器会影响成绩；强化学习奖励使用 Qwen3.6-Plus 作为模型裁判。作者做过文件层重合审计，但公开基准题文本是否进入各模型预训练语料无法完全排除。论文没有给出总训练 GPU 小时或完整美元成本，因此 4B 参数不等于低训练成本；两组公开基准的分数也不是所有办公岗位的真实完成率。

适合谁读。 文档智能体、办公自动化和 Agent 后训练团队。建议读第 3 节数据合成、第 4.2 节实验设置与主表、第 4.5 节消融，最后核对附录中的污染审计和评分器说明。代码：Agent-R²。
