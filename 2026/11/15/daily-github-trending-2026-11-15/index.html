2026-11-15 GitHub 热榜简报：Agent 的审查闭环、浏览器控制与本地基础设施

GITHUB TRENDING · 2026.11.15

今天的 GitHub all-languages 日榜把 Agent 的能力边界继续向外推：Plannotator和 OpenCodeReview把反馈、审查和证据接回开发流程，Modern Web Guidance与 AG-UI分别处理知识注入和界面协议，Chrome DevTools MCP、TensorFold和 LoopForge则把 Agent 带进浏览器、GPU 和可重复交付环境。真正值得观察的不是 stars 本身，而是这些项目如何划分权限、上下文、硬件和人类确认的边界。

Agent 审查浏览器调试现代 WebAgent 协议本地推理代码交付Office SDK自托管

今日要点

今天最清晰的主线是 Agent 开始拥有“控制面”：Plannotator把计划、文档、diff 和 PR 的人类反馈送回会话，OpenCodeReview用确定性流水线约束 LLM 审查，Modern Web Guidance把现代 Web 知识变成可检索的 skills，AG-UI则试图用事件协议把 Agent 接到真实界面。它们共同指向一个判断：提示词只是入口，稳定的接口、证据和人工确认才是可维护的工程结构。

另一条线是执行面下沉到真实运行环境：Chrome DevTools MCP进入浏览器调试，TensorFold绕过 Python 依赖直接调用本地 GPU，Univer把表格和文档能力嵌入产品，LoopForge用沙箱、SOP 和人类门控组织交付，Sure则提供了一个可运行的自托管业务应用样本。尝试这些项目时，先验证权限、模型端点、驱动、数据持久化和许可证，再把日榜热度当作决策依据。

值得尝试

backnotprop/plannotator

Plannotator 是面向 Claude Code、Codex、Copilot CLI 等编码 Agent 的本地浏览器审查层，可以标注计划、规格、HTML、Agent 消息、diff 和 PR，再把反馈送回会话。它适合需要在多 Agent 并行时保留人类决策入口的团队；限制是各宿主仍需通过插件、hooks 或 MCP 接入，兼容性和本地状态边界要逐一配置。主要语言为 TypeScript，日榜新增 408★；仓库页核验总计 11,168★，许可证为 Apache-2.0 / MIT，最近 Release v0.28.65 于 2026-11-15 发布。

GoogleChrome/modern-web-guidance-src

Modern Web Guidance 源仓库把现代 Web API、浏览器兼容、性能与无障碍知识组织成可安装的 Agent skills，CLI 支持 search、retrieve 和 legacy-scan。它适合前端团队或编码 Agent 作者学习如何把平台知识压缩成可检索规则；限制是它是指南与评估源代码，不是 Web 框架，结果仍需结合目标浏览器和真实测试。主要语言为 TypeScript，日榜新增 1,231★；仓库页核验总计 6,099★、Apache-2.0 许可证，最近 2026-11-14 UTC 提交。

ChromeDevTools/chrome-devtools-mcp

Chrome DevTools MCP 让编码 Agent 通过 MCP 或 CLI 控制并检查 Chrome，覆盖性能 trace、网络请求、控制台、截图、source map 和 Puppeteer 自动化。它适合做浏览器调试和性能工程的 Agent 化工具链；限制是官方只支持 Chrome 与 Chrome for Testing，浏览器内容会暴露给 MCP 客户端且 usage statistics 默认开启，需要按场景评估数据边界。主要语言为 TypeScript，日榜新增 664★；仓库页核验总计 56,337★、Apache-2.0 许可证，最近 Release v1.13.0 于 2026-11-11 发布。

alibaba/open-code-review

OpenCodeReview 是 AI 代码审查 CLI：把确定性的文件选择、规则匹配、评论定位与 LLM Agent 组合起来，支持 diff review 和整目录 scan。它适合做 CI review、代码质量或 Agent 工具链的人研究“确定性工程 × 动态决策”的边界；限制是需要可用模型端点，README 中的 benchmark 明确偏向高 precision、recall 较低，不能直接外推到你的仓库。主要语言为 Go，日榜新增 893★；仓库页核验总计 51,464★、Apache-2.0 许可证，最近 Release v1.13.9 于 2026-11-13 发布。

QwenLM/qwen-code

Qwen Code 是开源编码 Agent，覆盖终端、编辑器、桌面、浏览器和聊天入口，并把 Skills、SubAgents、MCP、记忆和多模型协议放进同一套工作流。它适合研究“Agent harness 如何跨模型与界面复用”；限制是当前迭代很快，部分能力仍是 experimental 或 1.0 Preview，安装主路径还要求 Node.js 22+。主要语言为 TypeScript，日榜新增 64★；仓库页核验总计 30,365★、Apache-2.0 许可证，最近 2026-11-15 UTC 提交。

dream-num/univer

Univer 是可嵌入产品的 Office SDK，提供表格和文档编辑、计算、协作、文件处理以及面向 Agent 的 Facade API；仓库核心是 Web SDK 的内容模型、命令、公式和渲染引擎。它适合研究如何把 Office 能力作为产品基础设施暴露给人和 Agent；限制是仓库的 Apache-2.0 部分主要是 Web SDK 核心，Server SDK、商业插件和商业 AI 扩展需要单独看许可与部署边界。主要语言为 TypeScript，日榜新增 495★；仓库页核验总计 24,525★、Apache-2.0 许可证，最近 Release v1.5.0 于 2026-11-14 发布。

ag-ui-protocol/ag-ui

AG-UI 是面向 Agent—用户交互的轻量事件协议，定义标准事件类型，兼容 SSE、WebSocket 和 webhook，并提供参考 HTTP 实现与 connector。它适合做实时聊天、生成式 UI、状态同步和 human-in-the-loop 的前端集成；限制是它只是协议层，不提供模型或 Agent，事件映射、错误处理和后端适配仍由集成方负责。主要语言为 TypeScript，日榜新增 9★；仓库页核验总计 17,389★、MIT 许可证，最近 Release 2026-11-13 发布。

ashhart/TensorFold

TensorFold 用 Zig 二进制直接在 Apple Silicon 的 Metal 和 NVIDIA GPU 的 CUDA 上运行语言模型 checkpoint，服务端不要求 Python 或 MLX 安装。它适合想研究本地推理、GPU kernel 和轻量 serving 路径的人；限制是硬件与运行时约束很强，Linux NVIDIA 路径要求 glibc 2.28+、R580+ 驱动和 CUDA 13.0，模型权重还各自拥有独立许可证。主要语言为 Zig，日榜新增 37★；仓库页核验总计 2,171★、Apache-2.0 许可证，最近 Release v1.2.9 于 2026-11-15 发布。

we-promise/sure

Sure 是已归档 Maybe Finance 的社区 fork，提供可用 Docker 自托管的个人财务应用，并覆盖浏览器、macOS、移动端、API 客户端和 LLM Agent 入口。它适合研究真实 Rails 业务应用如何在社区维护、自托管和多客户端之间折中；限制是社区 fork 需要自行承担备份、数据源和权限运维，README 也明确提示数据量较大时存在性能问题。主要语言为 Ruby，日榜新增 659★；仓库页核验总计 15,341★、AGPL-3.0 许可证，最近 Release v2026.11.14-alpha 于 2026-11-14 发布。

Tencent/LoopForge

LoopForge 是面向团队的自托管 Agent 交付工作区：在 Docker sandbox 中检出仓库、调用多个 coding-agent CLI、按角色协作，并用 SOP、checkpoint 和 human gate 产出 PR 或文档。它适合研究如何把一次性的“让 Agent 修 bug”变成可重复、可暂停、可审计的交付流程；限制是需要自有基础设施和多个外部 CLI，且版本仍为 release candidate，运行成本与权限配置不能省略。主要语言为 Go，日榜新增 33★；仓库页核验总计 932★，MIT（含第三方组件例外）许可证，最近 Release v0.3.9-rc.1 于 2026-11-13 发布。
