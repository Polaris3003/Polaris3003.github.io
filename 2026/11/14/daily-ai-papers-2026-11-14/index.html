Data-Efficient LLM Safety Alignment Guided by Interpretable Features

  • 作者：Hongyu Li、Zhan Yu、Zhe Zhao、Kimmo Yan、Xiong Kuang、Renfen Hu
  • 来源 / 分类：arXiv · cs.CL、cs.AI
  • 链接：摘要页 · PDF · arXiv DOI

全文状态与研究问题。 已核读 arXiv HTML 与 PDF 全文。论文关注安全微调数据过大且容易导致对无害请求过度拒绝的问题。LIS 用稀疏自编码器（SAE）激活找出覆盖多类安全特征的提示，再用多智能体对抗合成补充容易被误拒的无害提示。

方法、基线与作者报告的结果。 数据集仅 2.4K 条；作者在统一训练设置下与 TRIDENT-Core（26K）、TRIDENT-Edge（19K）、WildJailbreak（262K）及同规模随机子集比较，并在两个模型系列、4 个安全和 5 个过度拒绝基准上评测。作者报告 LIS 的安全性与可用性平衡更好；消融显示安全数据或无害拒绝数据单独使用都不够。LLaMA 3.1-Alpaca 上，SAE 筛选单样本成本为 H20 GPU 10.7 毫秒，低于论文比较的嵌入式 K-means 15.5 毫秒；LIS 微调使用 8 张 H20、两轮、0.99 GPU 小时。以上均是作者实验报告，不是独立复现。

创新、风险与失败条件。 贡献在于以可解释特征指导数据覆盖，显式平衡拒答与安全。基线采用统一训练设置，较大数据集比较有说服力；但作者未提供训练语料污染的系统审计。SAE 特征可能混入非安全语义，合成质量受生成模型能力限制，2.4K 数据也可能漏掉极端风险，测试仍是有限模型和基准的微调结果，不能直接等同部署安全。

适合谁读。 安全微调、拒答校准和训练数据工程团队。建议先读第 3 节数据选择与合成，再读第 4.2–4.5 节基准、消融和算力，最后看第 7 节局限。

Auditing AI peer reviewers: a benchmark on real scientific papers

  • 作者：'Iñigo Zubeldia、Boris Bolliet、Francisco Villaescusa-Navarro、Pablo Villanueva-Domingo、Miles Cranmer
  • 来源 / 分类：arXiv · cs.CL、astro-ph.IM、cs.AI、cs.DL
  • 链接：摘要页 · PDF · arXiv DOI · 代码/基准

全文状态与研究问题。 已核读 arXiv HTML 与 PDF 全文。论文测量 AI 审稿系统能否发现论文中客观、可定位的错误，以及它们会不会把干净论文误报。

方法、比较与作者报告的结果。 作者在天体物理与机器学习各选 15 篇近期 arXiv 论文，注入数学、数值、引文和一般问题四类、三个严重度共 357 个错误；比较 12 种审稿系统，包含单模型、Claude Code 配置和 Skepthical 多智能体工具链。Skepthical 检索引文、用计算代数查数学、运行代码核对数字。按论文级 bootstrap，天体物理语料中 Skepthical 总检出率 70.6%（95% 区间半宽 6.2），高于结构化 GPT-5.5 的 61.3%；机器学习语料中两者为 76.7% 与 81.1%，差异不显著。强模型使用相同提示时，总检出率仍相差约 50 个百分点。

创新、风险与失败条件。 贡献是把干净稿误报率和注入错误检出率同时纳入评测，并按错误类型拆分。它只检验客观、可定位的缺陷，不能代表新颖性、实验充分性或解释质量；每个领域仅 15 篇且每稿同时含多类错误。误报中的数学标记尤需谨慎；大部分裁定依赖 LLM，盲法人类复核只覆盖一篇论文。Skepthical 使用更多调用和三个模型提供商，比较不是等成本，收益不能单独归因于框架设计。代码、注入清单和裁定日志已发布。

适合谁读。 AI 审稿、科学工作流与自动化验证研究者。建议读第 2 节基准构造、第 3.1–3.2 节检出和误报、第 4 节局限，以及附录 M 的算力与成本。

CastWorld: Benchmarking Context-Aware Agentic Time Series Forecasting Beyond Predictive Accuracy

  • 作者：Bokai Pan、Ruijie Yang、Mingyue Cheng、Jiahao Wang、Xiaoyu Tao
  • 来源 / 分类：arXiv · cs.LG、cs.AI
  • 链接：摘要页 · PDF · arXiv DOI · 代码/数据

全文状态与研究问题。 已核读 arXiv HTML 全文；官方 PDF 链接可访问，但本次 PDF 抓取超时。论文问的是：在有外部信息和工具的交互式时间序列预测中，只看最终误差是否会漏掉代理如何搜证、改预测、选版本和消耗资源。

方法、比较与作者报告的结果。 CastWorld 含 25 个真实数据集、8 个领域、1,310 个任务回合和 49 个预测工具；15 个 LLM 在同一 250 个测试回合、相同历史、预测跨度和评分配置下比较，并与 ARIMAX、PatchTST、Chronos 等系统级预测基线对照。除预测误差外，评分还覆盖流程执行、可信行为和资源效率。作者的 CastWorld 预测系统在比较表中报告 MASE 0.8284、RMSSE 0.6869、平均名次 3.06；实验同时发现同等准确率的代理会表现出不同决策轨迹，额外交互不一定改善结果，允许搜证后修订则提高了三种被测模型的任务感知预测分数。

创新、风险与失败条件。 任务清单、候选、结果和依赖配置在代码库中提供，有利于复跑；测试上下文有截止时间、隐藏未来目标，并人工复查可能的目标泄漏。主要限制是人工整理的25个数据集和固定250回合，公开历史数据仍可能与模型训练语料重合，论文未给出完整的预训练污染审计。模型的工具、预算和推理配置也不同。附录报告 GPT-6 Astra 每回合平均约 345.8 秒、40.1 万输入输出 token，资源成本会显著改变比较结论。

适合谁读。 时间序列代理、金融预测系统和工具使用评测团队。建议读第 3 节交互框架、第 4 节任务集、第 5 节评测指标、第 6.1–6.5 节结果，及附录 A.4 的资源消耗。

MLIRBench - A Benchmark and Dataset for Compiler and Hardware-Aware Reasoning

  • 作者：Pranava Sai Maganti、Meghasyam Peddireddy、Muzakker Hossain、Kaining Gao、Farhan Ahmed、Ali Jannesari
  • 来源 / 分类：arXiv · cs.PL、cs.AI、cs.LG
  • 链接：摘要页 · PDF · arXiv DOI

全文状态与研究问题。 已核读 arXiv HTML 与 PDF 全文。论文检验 LLM 能否判断编译器中间表示（MLIR）程序对的语义关系，而不只是识别熟悉的代码模式。

方法、基线与作者报告的结果。 多智能体流水线生成程序变体，再通过编译执行得到 EQUIV、DIVERGE 或 ERROR 标签；基准含 1,768 对程序（torch 888、linalg 880）。9 个模型（5 个开放权重、4 个专有模型）使用相同提示模板、温度 0 和确定输入。作者报告 Gemini 3.1 Pro 标签准确率最高，为 92.65%，但详细结果行为分仅 5.04/10，说明标签分类正确并不意味着能准确解释实际运行结果；全体模型平均标签准确率 74.59%，平均结果行为分 3.63/10。

创新、风险与失败条件。 执行派生标签比单纯 LLM 裁判更可审计，并惩罚没有依据的解释。比较提示和输入较一致，但评估同时混有闭源与开放权重模型，API 价格、延迟和算力并未等成本归一；解释分仍依赖固定 LLM 裁判，不能当作绝对理解能力。数据由 40 个手工种子程序生成，限于 torch/linalg 两种 dialect 和固定 IREE 环境，未覆盖更广泛的真实编译变换。全文未展示系统化的模型训练数据污染审计。

适合谁读。 编译器、代码模型和程序验证研究者。建议读第 3–5 节基准生成、数据集与模型结果，再看第 6.5 节局限和附录 D/E 的提示、记录及评分协议。

Outcome-Mass Alignment: Controlling Length-Dependent Trajectory Influence in Multi-Turn LLM Agent Reinforcement Learning

  • 作者：Dawei Zhang、Yubin Huangfu、Jessica Fan、Boyu Wei、Likang Wu、Hongke Zhao、Ming He、Zhu Teng
  • 来源 / 分类：arXiv · cs.CL
  • 链接：摘要页 · PDF · arXiv DOI

全文状态与研究问题。 已核读 arXiv HTML 与 PDF 全文。多轮代理训练把一条交互轨迹拆成多行和 token 后，长轨迹可能因结果被重复计入、优化目标按 token 赋权而获得不成比例的训练影响。OMA 将这两个外层记账选择拆开控制：Outcome Alignment 按唯一轨迹统计结果，Mass Alignment 再按轨迹平均优化目标。

方法、基线与作者报告的结果。 作者用 Qwen2.5-1.5B/3B-Instruct，在 ALFWorld、WebShop 上以 GRPO 为主基线，并做 GiGPO、GSPO 兼容性比较。ALFWorld 两种规模的主实验中，GRPO 端点成功率分别由 73.4% 提至 82.8%、74.2% 提至 81.2%。在 WebShop-SOL，成功率 nAUC 从 39.9% 提至 51.1%；但普通 WebShop 3B 设置端点成功率由 64.8% 降至 57.0%，效果依赖长轨迹与失败结果的相关结构，并非普遍增益。主实验每种配置主要报告单一 seed；附录两 seed 的补充运行是描述性证据。训练使用四张 GPU。

创新、风险与失败条件。 该方法修正轨迹被拆分后的样本权重，不改变优化器内部 credit assignment、importance ratio 或 clipping。相同任务与配置的对照较直接，但只有少量环境、模型尺度和更新步数；公开基准的任务记忆/污染没有单独审计。普通 WebShop 出现回退，作者也指出扩展长度与结果关联弱或反向时效果会混杂。

适合谁读。 多轮 Agent RL、GRPO 数据管线和长上下文训练团队。建议读第 3 节两种对齐定义、第 4.1–4.4 节实验与消融、第 4.7 节边界案例，及附录 C/D 的运行与多 seed 证据。
