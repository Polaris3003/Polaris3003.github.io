Knowing When to Intervene: Causal Evaluation of AI Agents（arXiv:2611.09792）

全文状态与问题。 已核阅公开 PDF。静态成功率无法回答“某个动作现在要不要人工复核”。作者让工具调用在轨迹中的每个合格节点以 1:1 随机分配为复核或直接执行；同一批轨迹由此估计即时干预效应、后续不再干预时的效应，以及选择性干预策略的整体增益。方法上，随机延续效应用交叉拟合 AIPW，另外两种使用结构嵌套均值模型与 g-estimation；不需要读取模型内部状态。

作者报告的结果与比较。 在 tau-bench Retail 和 ToolSandbox，智能体为 GPT-5 nano、Claude Haiku 5.5，复核者为 GPT-6 Luna；ImpossibleBench 使用 Qwen3.5 Flash。Retail 中，GPT-5 nano 的读写复核总体为正，但效果集中于客户识别、订单详情、取消订单和修改商品等具体动作；Claude 的广义读调用效果接近零，账号详情子组却为正。ToolSandbox 的“时间与计算”能力总体估计 +1.8 分，95% 区间为 [-0.2, 3.8]，不能排除零；其中时间戳构造工具为 +6.9 分，区间 [1.2, 12.6]。这说明按工具/状态细分比“一律复核”更有信息。

方法价值与证据边界。 贡献是把复核作为可随机化的动态处理，而不是只从事后成功/失败轨迹猜因果。点位随机化支持即时效应识别；无后续干预和政策增益还依赖额外 SNMM 设定。结果来自三套基准、少数模型和固定 GPT-6 Luna 复核器，不证明同一策略在真实用户、不同工具或昂贵的人审下同样有效。论文建议把高风险工具作为后续独立随机试验的候选。

适合谁读。 负责智能体上线审计、工具权限和因果评估的研究者/工程师。建议读第 2.2–2.4 节随机设计与识别、第 3.1–3.3 节分任务结果，再看附录 B 的实验协议。代码：作者仓库。

Refer-CityFlow and M3Track: A Benchmark Dataset and Reference Framework for Language-Driven Multi-Target Multi-Camera Tracking（arXiv:2611.08976）

全文状态与研究问题。 已核阅 arXiv HTML 全文；PDF 体积过大，改读实验、消融和限制章节。研究对象是跨多个顺序、稀疏重叠摄像头，用自然语言持续跟踪同一目标，已有单摄像头 Refer-MOT 不能覆盖。Refer-CityFlow 从 CityFlow 身份标注出发，含 96 段视频、40 台路侧摄像头、660 多条跨镜轨迹、4,362 条轨迹描述和 7,699 个查询，其中 1,699 条来自 50 位真实用户。M3Track 用 GPT-4o-mini 解析查询，调用可替换的检测、OC-SORT 跟踪与跨镜轨迹合并模块；不在本基准微调，实验使用一张 A100-80GB。

关键结果与基线。 在真实用户查询上，M3Track 的 YOLOv5+SVM 设置 HOTA 为 42.93、IDF1 为 56.15；更换检测器后，Grounding-DINO 配置的结果达到摘要报告的 44.10 HOTA、65.40 IDF1。单摄像头 TransRMOT/TempRMOT 在同协议下为 18.28/14.95 HOTA；直接迁移的 CRTrack 约 0.05。AI 生成查询的 M3Track+OmDet-Turbo 为 31.08 HOTA、43.18 IDF1。空间约束子集移除交互式查询澄清后，HOTA 从 47.4 降至 35.6。对照并非完全同能力基线：TransRMOT/TempRMOT 本来没有跨镜关联，得分应看作参照；不同检测器导致的差异也大于 LLM 解析器差异。

创新、局限与失败条件。 基准同时保留机器生成和自然用户查询，并将目标轨迹、语言消歧、跨镜身份关联拆开。主要限制是详细实验集中在 Scenario 02，用户只来自 50 人，跨城市、摄像头拓扑、夜间/遮挡和更长时间跨度未验证；作者指出机器生成查询有语言规律。44.10 的高分依赖检测器和整套流水线，不应归因于 LLM 自身。项目代码：Refer-CityFlow 与 M3Track。

适合谁读。 多目标跟踪、视频检索、视觉智能体和交通摄像头系统团队。建议读第 3 节数据与协议、第 4 节模块设计、第 5.1–5.3 节结果/消融及第 6 节限制。

DecoyCount: Evaluating Visual-Reasoning Misalignment in Counting（arXiv:2610.34855）

全文状态与问题。 已核阅 arXiv HTML v2 全文。普通计数分数把“没看见目标”和“看见但按错规则数”混在一起。作者在 1,586 张真实图像上设计七类诱饵，共 2,108 个诱饵；每题配中性提示、只提示所需计数规则但不泄露答案的对齐提示，以及带真实情境/多图的多跳提示。六种前沿模型、尺度和思考预算对比，并用通用代码执行与 SAM3 定向视觉工具测试。

作者报告的结果与公平性。 中性提示准确率约 17.1%–43.1%，六个前沿模型中，五个更常输出预设诱饵而非真值；匹配规则提示提高 12.1–22.1 个百分点，修复错误的次数为破坏正确回答的 2.7–6.8 倍。控制实验显示扩大模型或思考预算虽提高准确率，推理对齐差距却分别扩大约 4.52 和最多 11.84 个百分点；通用代码执行也会扩大 2.48–7.17 点，SAM3 定向视觉工具在对应比较中缩小 4.52 点。提示对照包含泛化“仔细数”和错误规则提示，因而比只报单个模型总分更能隔离任务路径选择。

创新、局限与可复现性。 它把可解释错误诱因和配对提示加入计数基准，且开放评测代码：DecoyCount。但图像及诱饵经委托、编辑和筛选，候选题先由模型门控，再经人工审查；“正确计数规则”仍依赖题面与人工判断。作者未给出模型训练语料污染审计，不能排除公开图片或题目被预训练见过。闭源模型、思考 token 和工具调用也有运行成本，摘要中的百分点不能当成现实视觉能力的普遍提升。

适合谁读。 视觉语言模型评测、视觉推理与工具调用团队。建议读第 3 节诱饵设计、第 4 节跨模型结果、第 5.1–5.3 节对齐/工具分析，再看附录 C 的外部效度与附录 A 的数据筛选。

Safety and accuracy diverge across deployment conditions in clinical large language models（arXiv:2605.04039）

全文状态与问题。 已核阅 arXiv HTML v2 全文。论文检验“平均准确率更高就更安全”是否成立。SaFE-Scale 在 200 道文本放射科选择题 RadSaFE-200 上评估 34 个本地运行的 LLM，固定题目、选项与评分，只改变闭卷、临床干净证据、加入干扰证据、标准/智能体 RAG、长上下文及推理计算等部署条件；每个错项另标高风险、不安全和证据矛盾。

关键结果与基线。 作者报告，给模型知晓正确答案后撰写的干净临床证据作为上界，使平均准确率由 73.5% 升至 94.1%，高风险错误从 12.0% 降至 2.6%，危险过度自信从 8.0% 降至 1.6%。标准与智能体 RAG、长上下文和更多推理只改善部分指标，未复制这一安全组合。危险过度自信是重复采样稳定性指标，不是校准后的正确概率；论文的方差分解也把部署条件而非模型家族排在安全差异之前。

局限、基线公平性与污染。 干净证据含答案信息，属于不可直接部署的 oracle 上限；冲突证据也只是轻度扰动，不是真实检索噪声。实验只用单一文本放射科基准，没有影像输入、患者结局或医生工作流；第二位盲标注者的三类安全标签一致率约 59.8%、79.4%、61.7%，说明风险标签本身存在判断差异。全文未见训练语料污染审计，也未给出跨机构复现成本；结果不能外推为临床安全认证。

适合谁读。 医疗 AI 安全、RAG 评估和模型部署团队。建议读第 2 节标签定义、第 3 节六种条件、第 4 节结果及第 6 节限制。

On Agentic Manipulation Policies（arXiv:2611.09892）

全文状态与研究问题。 已核阅 arXiv HTML 全文。AMP1 让通用多模态模型留在控制回路中，以自然语言理解任务、调用 Python 生成动作轨迹、观察执行后调整计划；基础套件不提供抓取/放置技能，也没有示范或任务专门训练。作者在 RoboLab-120、CaP-Gym、RoboDojo 和真实机器人上与 VLA、WAM、技能编排或代码合成基线比较。

结果、基线与算力成本。 RoboLab-120 摘要给出的零样本成功率为 85.6%，对应专用 VLA/WAM 为 49.2% 和 42.9%；在选取的 108 次实体机器人试验中成功 104 次，而不启用错误恢复时为 94/108。另一组完整 1,200 次 RoboLab 评测中 Gemini 4 Argon 成功 1,027 次、Opus 5.5 为 994 次。与基线使用同一初始物体位置、任务说明和 5 分钟动作时限，但部分辅助/记忆型基线会从被评任务回合中改进，不能都视作零样本同条件比较。按公开 API 标价估算，Opus 5.5 每个 RoboLab 回合约 1.39 美元；加深思考可提高部分模型成功率，同时显著增加费用。

创新、失败条件与复现。 直接闭环控制比离线写完程序或调用固定技能更灵活。作者也发现失败不能全归咎于策略：约三分之二失败来自物体尺寸不适配夹爪或评估器拒绝合理结果；其余包括超时、掉落、碰撞、误读指令及 API 安全拦截。模型通过供应商 API，开放权重模型则用多张 H100/B200，真实机器人工作站用两张 RTX Pro 6000；系统可复现成本不低。模型训练数据是否见过相关任务没有污染审计，实测只覆盖少量机器人与任务，也不等于家庭通用能力。

适合谁读。 具身智能、机器人控制和长时程智能体团队。建议读第 2A 节零样本基准、第 2B 节涌现策略、第 2D 节模型/传感器分析、第 4F–4G 节实机协议与算力，以及附录 S6–S7 的失败与费用。
