用人类对齐的 LLM-as-a-Judge 评估药物发现 agent

论文：Designing a Robust LLM-Based Evaluation System for Agentic AI in Drug Discovery Through Human Alignment（arXiv:2608.21057）
作者：Emma Granqvist、Rocío Mercado、Samuel Genheden
来源/分类：arXiv · cs.LG
全文状态：已核阅公开 PDF。

论文研究的问题不是 ChatInvent 能否生成一段看似合理的回答，而是开放式、可调用工具的药物发现 agent 能否被稳定、可扩展地评价。作者为输出定义 Completeness、Relevancy、Structural Clarity、Scope Adherence 四个 LLM 评审维度，并把 Tool Call Correctness 作为确定性检查；随后让 5 名专家给 30 个样本标注，比较 Gemini 3.1 Pro、Claude Opus 4.7、GPT-5 和 Llama 3.1 70B 四个候选评审器，再用 20 个样本做 DSPy few-shot 优化、10 个样本做验证，最后在 70 个留出问题上评估 ChatInvent。这里的“对齐”是评审器与人工多数票的一致性，不是 agent 的科学发现已被独立验证。

作者报告最佳评审器经少样本优化后与人工多数票的平均对齐从 0.80 提升到 0.86。在 70 个留出问题上，ChatInvent 的 Tool Call Correctness、Relevancy、Structural Clarity、Scope Adherence 平均分别约为 90%、86%、90%、84%；Completeness 只有 43% 被评为完整，另有 39% 部分完整，常见缺陷是遗漏 CSV 路径、表格或请求的分子属性。论文的创新在于把评审器本身当作需要验证的测量仪器；局限也很明确：只有 5 名专家、单一 agent、30 个对齐样本，模型和提示会持续变化，LLM 评审有成本与偏差，且实验没有证明输出在真实药物研发中的正确性。适合 agent 评测、科学 AI 和 LLM-as-a-Judge 工程读者；建议优先读摘要、§3 ChatInvent、§4 评估框架、§5 对齐实验、§6 结果和 §7 讨论。

Trustworthy RAG：能拦截显式投毒，但不能把隐性改写当作已解决

论文：Trustworthy RAG: An Evaluation Agent for Detecting Misinformation and Knowledge Poisoning in Generative AI Systems（arXiv:2608.21095）
作者：Balkrishna Giri、Md Toufique Hasan、Jussi Rasku、Muhammad Waseem、Pekka Abrahamsson
来源/分类：arXiv · cs.SE、cs.AI、cs.CL、cs.CR、cs.IR
全文状态：已核阅公开 PDF。

论文把 RAG 的风险拆成“检索相关但事实不真”的安全—可靠性缺口，提出一个生成前中间件：用 NLI 做事实性核验，用五类信号检测知识投毒，再以 T = 0.4F + 0.35C + 0.25(1-P) 汇总为 Trust Index，并对高污染上下文施加非线性惩罚。实验使用 TruthfulQA、FEVER，以及包含 40 条 OWASP/CWE 规则的安全编码知识库；主配置以 Llama 3.3 70B 生成、MiniLM 向量检索，比较 Qwen 3.5 35B、Mistral 7B 等模型，并将矛盾、指令注入、实体替换和细微语义弱化分开测试。

在 TruthfulQA 的混合攻击设置中，作者报告 91% 准确率、100% 精确率、40% 召回率和 57.1% F1；指令注入的召回率为 100%、F1 为 96.8%，但实体替换召回率为 0%，细微语义操纵召回率只有 20%。跨模型 ROC-AUC 约为 0.73–0.81，按模型校准阈值后可恢复部分性能；在安全编码场景中，指令注入 F1 为 92.3%，而矛盾和细微弱化仍为 0% 召回。代价是每个样本约增加 14.7 秒、约为普通 RAG 的 17 倍。最重要的证据边界是：论文测量的是投毒上下文的检测，不是下游 LLM 是否真的采纳了错误信息；攻击样本是规则构造的，FEVER 上准确率降到 73%、低于 85% 的朴素基线，且按文档标注的召回还是偏保守。适合 RAG 安全、知识库治理和安全编码流水线读者；建议读摘要、§III Trust Index、§IV 实验设计、§V-A/C/F/G 和 §VI 局限。

CRATE：把移动 agent 评估拆成逐步后果推理，降低长轨迹上下文负担

论文：Automated Trajectory Evaluation for Mobile Agents via Step-Level Consequence Reasoning and Aggregation（arXiv:2608.20797）
作者：Pengshuai Yang、Zijing Gao、Xue Yu、Benhui Zhuang、Bo Yuan、Junlan Feng
来源/分类：arXiv · cs.AI
全文状态：已核阅公开 PDF。

论文针对移动 agent 的两个评估问题：一次性把完整轨迹交给 VLM 会造成上下文过载，而只看任务完成又会漏掉操作安全。CRATE 先在每一步提取与任务有关的视觉线索、推断动作导致的状态变化，再把逐步证据聚合成轨迹级完成度判断；CRATE-S 在同一框架上定位操作风险。作者用 Qwen2.5-VL-72B-Instruct 和 GPT-4o-1120-128k 作评审器，与 SPA-Bench、A3 的最终状态/关键状态版本比较，并在 AndroidWorld、CRATEBench、MobileRisk 上评估；安全实验另与规则法、基础 VLM 和 OS-Sentinel 对比。

作者报告在 AndroidWorld 上，Qwen 评审器的 CRATE 准确率/F1 为 0.930/0.833，GPT-4o 为 0.904/0.756；在更复杂的 CRATEBench 上分别为 0.839/0.815 和 0.806/0.760。MobileRisk 上，Qwen 版 CRATE-S 的轨迹级 F1 为 0.697、逐步风险分数为 28.8，高于 OS-Sentinel 的 0.630 和 23.5；去掉逐步后果推理后，Qwen 在 CRATEBench 的 F1 从 0.815 降到 0.649。创新是把“动作—状态变化—轨迹结论”做成可解释中间证据，而不是把长截图序列整体交给裁判。局限是只验证了移动场景、全部是事后评估，尚未证明可作为在线奖励或实时反思模块，且性能受底层 VLM 能力约束。适合 GUI/mobile agent 评测、安全监控和 VLM 工程读者；建议读摘要、§3 CRATE/CRATE-S、表 2–4、§5 实验和末尾 Limitations。

SUSVIBES：功能测试通过，不代表 agent 生成的代码安全

论文：Is Vibe Coding Safe? Benchmarking Vulnerability of Agent-Generated Code in Real-World Tasks（arXiv:2512.03262）
作者：Songwen Zhao、Danqing Wang、Kexun Zhang、Jiaxuan Luo、Zhuo Li、Lei Li
来源/分类：arXiv · cs.SE、cs.CL
全文状态：已核阅公开 PDF。

论文把“vibe coding 是否能直接进入生产”具体化为仓库级安全测试。SUSVIBES 从真实开源项目中的漏洞修复提交构造 186 个功能请求任务，保留完整仓库上下文，并为每个任务同时准备功能测试和安全测试；任务平均上下文约 236K 行、1,186 个文件，覆盖 10 个应用领域。实验组合 3 个 agent 框架（SWE-Agent、OpenHands、Claude Code）与 4 个模型，采用 pass@1，分别报告 FuncPass（功能正确）和 SecPass（功能与安全都正确），再测试让 agent 自选 CWE 或直接给出漏洞类型的轻量缓解。

作者报告 SWE-Agent + Claude 4 Sonnet 的 FuncPass 为 57.0%，但 SecPass 只有 11.8%；也就是说在其功能正确的解中，约 79.3% 仍不安全。四个模型的安全率在共同功能正确子集上为 18.3%–30.4%，框架之间为 17.4%–23.3%；给出安全提示或 oracle CWE 只把该配置的 SecPass 从 11.8% 提到 14.5%/15.1%，同时降低功能通过率。论文还给出具体的 Django 密码校验时序侧信道案例，说明漏洞可能来自正确功能路径中的边界处理。价值在于把安全作为独立可执行的验收条件；限制是任务来自可观测漏洞修复、只覆盖其测试能捕获的安全性质，结果是特定模型/提示/环境下的 pass@1 快照，不等同生产事故率或未来模型必然表现。适合代码 agent、DevSecOps 和软件供应链治理读者；建议读摘要、§3.3 基准构造、§4.1–4.3、§5 缓解和附录 B 的筛选流程。

链接：arXiv 摘要页 · PDF · 代码与数据 · 排行榜

aiXamine：可信度是多维向量，单一总分会掩盖安全—隐私—可用性冲突

论文：aiXamine: Unified Black-Box Evaluation of Cross-Dimensional Trade-offs in LLM Safety, Security, and Privacy（arXiv:2608.20554）
作者：Fatih Deniz、Yazan Boshmaf、Dorde Popovic、Issa Khalil
来源/分类：arXiv · cs.CR、cs.LG
全文状态：已核阅公开 PDF。

论文提出 SSP（Safety、Security、Privacy）框架，将 46 个测试、9 个服务放到同一黑盒评测协议中，覆盖越狱、代码安全、幻觉、过度拒答、隐私泄露、公平性和分布外鲁棒性等。作者在相同推理条件下评估 121 个闭源与开放权重模型、超过 5,000 次测试，并用规则、多裁判和外部审核器组合打分；同时用 6 个部署画像和 10,000 个 Dirichlet 权重向量检查总分排序的稳定性。比较重点不是“谁的总分最高”，而是同一模型在不同风险维度上的取舍。

作者报告安全服务与过度拒答存在负相关，越狱鲁棒性与可用性相关系数为 −0.39；隐私与其他维度的平均绝对相关约为 0.13，说明标准安全对齐不能代替隐私评测。部署画像改变后，前 15 个模型的第一名在 6 个画像中的 4 个发生变化，GPT-4o 的名次最多摆动 13 位；同一基础架构的 R1 式离线蒸馏还把对抗鲁棒性从 56.9 降到 2.6。创新是把跨维度 trade-off 和排序敏感性作为一等公民，而非把安全、隐私、可用性分别报表。限制包括只测英文、黑盒文本交互、自动裁判与二元安全标签的误差、供应商版本差异和聚合权重选择；这些是作者在自有基准上的比较结果，不是对真实事故概率的估计。适合模型选型、红队评测和安全治理读者；建议读摘要、§3 测试体系、§4.2–4.6、§6 局限和附录测试清单。

链接：arXiv 摘要页 · PDF · 评测门户

来源/分类：arXiv · cs.NE、cs.AI
链接：arXiv 摘要页 · PDF

仅依据摘要：论文提出用 Clarifine/Confusionin 两个递归信号调节状态更新、停止和记忆检索的稀疏递归架构，并给出收缩、Lyapunov、Euler–Maruyama 等分析。在可验证的 Maze 实例中，自适应停止把平均深度从 20.00 降到 11.31；兼容的重复 Sudoku 中 warm-start 把深度从 18.39 降到 2.00，摘要还称在欺骗性平台期有优势、在同质高斯噪声下没有优势。证据主要来自作者设计的模拟和任务，ARC 只用于操作迁移性；摘要明确不能证明优于独立训练的外部架构，算力和基线公平性仍需核验。

Is Vibe Coding Safe? Benchmarking Vulnerability of Agent-Generated Code in Real-World Tasks

作者：Songwen Zhao、Danqing Wang、Kexun Zhang、Jiaxuan Luo、Zhuo Li、Lei Li
来源/分类：arXiv · cs.SE、cs.CL
链接：arXiv 摘要页 · PDF · 代码与数据 · 排行榜

已在重点关注中核阅全文。SUSVIBES 把真实仓库中的功能正确和安全正确分开计分，最强示例的功能通过率 57%、安全通过率 11.8%；安全提示只带来有限改善并牺牲功能。它是安全验收基准，不是对所有代码 agent 生产事故率的估计，测试覆盖、漏洞分布、模型版本和任务选择都决定了外推边界。

ClawSentry: A Progressive Multi-Tier Security Monitor for Safeguarding Autonomous LLM Agents

作者：Kai Wang、Zeming Wei、BiaoJie Zeng、Chang Jin、An Wang、Xiaokun Luan、Zhixiao Lin、Jingjing Qu、Xia Hu、Xingcheng Xu
来源/分类：arXiv · cs.CR、cs.AI
链接：arXiv 摘要页 · PDF · 代码

仅依据摘要：ClawSentry 将 agent 风险分成技能准入、调用意图、执行效果和事后后果四个位置，先做技能包审查，再以确定性 L1、规则锚定的 L2 和只读 agent L3 逐级升级，并用会话级机制识别换工具或改写措辞的重试。作者报告在 SkillInject/Codex-GPT-5.4 上 ASR 从 39.55% 降到 2.61%，干净技能的 TSR 从 83.78% 变为 83.05%；五个 work agent 上 ASR 降到 9.09%–15.03%，干净技能 TSR 为 98.7%。摘要未说明各层延迟、误报、完整威胁覆盖和真实部署流量，ASR/TSR 也来自受控基准，不应直接当作生产安全率。

CAS: Conformalized Agentic Search via Adaptive Retrieval and Policy Weighting

作者：Zixi Zhu、Jiayuan Su、Jian Zhang、Yu Lin、Hongwei Wang
来源/分类：arXiv · cs.AI
链接：arXiv 摘要页 · PDF · 代码

仅依据摘要：CAS 用 conformal prediction 的 APS 构造自适应大小的检索文档集合，再用 ACI 估计答案置信度，将低置信轨迹纳入 GRPO 的惩罚项，目标是同时减少证据遗漏、噪声和冗余搜索。作者在单跳和多跳问答上报告准确率提高、工具调用明显减少。摘要没有给出覆盖率保证所需的交换性条件、校准集规模、不同 K 的调用成本或各基线数字；因此“可靠高效”仍是作者在这些 QA 基准上的报告，不能推广为所有 agent 搜索场景的统计保证。

AGIDefect-4K: A Richly Annotated Dataset for AI-Generated Image Defect Detection, Localization and Explanation

ArtiMo: Agent-Driven Articulated Mesh Animation

aiXamine: Unified Black-Box Evaluation of Cross-Dimensional Trade-offs in LLM Safety, Security, and Privacy
