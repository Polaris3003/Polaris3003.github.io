1. FineVLA：让机器人语言真正约束“怎么做”

论文：FineVLA: Fine-Grained Instruction Alignment for Steerable Vision-Language-Action Policies（arXiv:2605.27284）
作者：Xintong Hu、Xuhong Huang、Jinyu Zhang、Yutong Yao、Yuchong Sun、Qiuyue Wang、Mingsheng Li、Sicheng Xie、Yitao Liu、Junhao Chen、Yixuan Chen、Yingming Zheng、Shuai Bai、Tao Yu
来源/分类：arXiv · cs.RO、cs.AI
全文状态：已核阅公开 PDF（39 页）

核心问题：大多数机器人轨迹只有“抓杯子”这类目标级描述，没有说明使用哪只手、从哪个方向接近、在哪里接触或如何恢复失败。论文问的是：把这些执行细节写进监督，能否让 VLA 策略在不牺牲任务完成率的前提下变得可操控。

方法与基线：FineVLA-Tool 统一 10 个开源机器人数据集的 972,247 条轨迹、约 85K 个任务，通过聚类采样后形成 47,159 条人工核验的细粒度轨迹，覆盖十类执行属性。作者另外构建含 500 个视频、11,631 个原子事实和 1,030 个 VQA 问题的 RoboFine-Bench，并训练 RoboFine-VLM 做可扩展标注。策略实验在 RDT-OFT、RDT-GR00T 和 AlohaMix-OFT 上固定视觉、动作与轨迹，只改变 Raw-only、FG-only 以及 FG:Raw 混合比例；模拟评测每任务 20 个 episode，真实评测在 Cobot Magic 双臂平台上用近似相同场景的成对指令隔离颜色、姿态、接近方向、旋转方向和主动臂。

作者报告的结果：RoboFine-VLM 在留出的 RoboFine-Bench 上达到 68.2% VQA 准确率，困难 caption 轨道得分 82.2%，高于所比较的通用模型。RoboTwin 中，AlohaMix-OFT 的 FG:Raw=1:1 达到 Easy/Hard 86.8%/82.5%，相对 Raw-only 的 71.8%/71.4% 提升 15.0/11.1 个百分点；FG-only 也在三种设置中优于 Raw-only。真实双臂评测的平均任务分从 Raw-only 的 49.9/100 升到混合监督的 62.7/100，姿态、颜色和接近方向分别提升 23、18 和 18 分。作者观察到 FG:Raw 约 1:2 到 1:1 呈稳定倒 U 曲线，说明细粒度语言更像目标级指令的补充，而不是替代品。

创新、局限与失败条件：贡献在于把动作对齐的数据工具、留出的视频理解基准、专用视觉语言标注器和策略训练配方放在一个可复现闭环中。真实验证仍局限于桌面双臂和少量定向任务，未解决未见过的主动臂—目标组合：OOD 探针的最高得分只有 10/100。人工核验没有被完全消除，caption 的反幻觉指标也主要覆盖动作步骤。训练规模包括 100k steps、64 张 A100 的预训练配置，部署成本不能由“任务成功率提升”忽略；论文报告的数字是作者实验，不是独立复核结论。

适合谁读：机器人 VLA、具身数据工程和可控策略研究者。建议优先读 §1、§2 的数据与基准、§4.2–§4.4 的 VLM/模拟/真实实验，以及 §5.4–§5.5 的因素级控制和失败分析。项目页：finevla.xlang.ai。

2. TOP-R：工具编排会把“无害碎片”拼成隐私泄露

论文：Agent Tools Orchestration Leaks More: Dataset, Benchmark, and Mitigation（arXiv:2512.16310）
作者：Yuxuan Qiao、Dongqin Liu、Hongchang Yang、Wei Zhou、Songlin Hu
来源/分类：arXiv · cs.CR、cs.AI、cs.CL
全文状态：已核阅公开 PDF（20 页）

核心问题：一个银行记录、一个日历条目或一个联系人返回值单独看都不揭示敏感结论，但智能体可能把它们合并后主动说出用户没有要求的健康、财务、法律或求职信息。论文将这种单智能体、多工具、无攻击者参与的组合推断风险形式化为 TOP-R，并问现有提示防护是否足够。

方法与基线：作者用四类 grounding library 通过 LRSE 反向构造 1,000 个合成实例，固定 6 个候选工具、两阶段工具选择/回答流程，并用 C1 结论敏感、C2 单源不可推断、C3 多源可推断三道门筛选。指标分开报告任务完成率 CR、泄露率 LR 和二者的调和平均 H-score；基线包含 6 个 LLM agent，提示实验比较 Task-Necessary Minimality、Context-Bounded Disclosure 和 Law-and-Policy，参数更新方法 TOP-Align 采用 SFT+DPO。

作者报告的结果：六个 agent 的平均 CR 为 98.0%，但 LR 达到 88.6%，H-score 只有 20.4；不同模型的 CR 都超过 96%，因此这里不是普通任务失败，而是“成功完成任务同时泄露”。CTD 从 2 增到 5 时，LR 从 78.7% 升至 93.4%。开启原生 reasoning 后，最终回答泄露率平均仍为 81.4%，暴露推理轨迹泄露率为 82.4%。仅提示的最低 LR 仍为 69.8%；在独立 500 实例的后训练评测中，TOP-Align SFT+DPO 的 CR/LR/H-score 为 97.4%/64.8%/51.7%，相对基线 H-score 提升 16.2 分，但没有消除泄露。

创新、局限与失败条件：论文把隐私边界从“单条工具返回是否含秘密”推进到“多条合法返回是否可组合推断”，并把任务效用与非披露放到同一指标中。TOP-Bench 是受控合成基准，不是线上流量样本，不能估计真实系统的泄露发生率；隐藏内部状态、工具调用日志、记忆和下游传播也未测量。判断依赖模型辅助的 judge-and-audit 流程，TOP-Align 只在一个基础模型和独立 split 上评估，提示与后训练都可能受基准构造分布影响。

适合谁读：工具调用 agent、隐私工程、安全评测和企业数据治理读者。建议优先读 §3 的形式化、§4 的 LRSE/TOP-Bench、§5.3–§5.6 的基线与 reasoning 诊断、§6 的缓解实验和 Limitations。代码与数据：TOP-R GitHub。

3. Incremental Pooled LLM Evaluation：把 RAG 评测变成可复用资产

论文：Incremental Pooled LLM Evaluation for Cost-Effective Retrieval Model Selection（arXiv:2609.02745）
作者：Max Nelson、Hanoz Bhathena、Aviral Joshi、Saket Sharma
来源/分类：arXiv · cs.IR、cs.CL
全文状态：已核阅公开 PDF（10 页）

核心问题：生产 RAG 不断加入新的 embedding、BM25 或 hybrid 检索配置，如果每次都重新让人或 LLM 标注全部 query-document 对，评测成本会随系统数量线性重复。论文问能否只标注候选系统检索结果的并集，并在新系统加入时只补标它带来的新文档。

方法与基线：对每个 query，作者把 11 个 dense、sparse 和 hybrid 系统的 top-100 文档合并，用固定版本 GPT-4.1 以 0/1/2 三档相关性评分，再复用 qrels 计算 P@k、Recall、nDCG 和 MAP。方法在 FiQA、TREC-COVID、Natural Questions 和 FinRAGBench-V 四个公开基准上与人工 gold qrels 比较，并在金融新闻 QA 中评测 62 个检索配置；基线是每个系统独立标注以及传统只把池外文档当作不相关的 pooling。

作者报告的结果：四个公开基准的 pooled LLM 排名与 gold 排名的 nDCG@10 Spearman 相关系数为 0.69–0.95，作者称考虑 qrels bootstrap 不确定性后有 97% 的成对系统排序得到保留；更细看 nDCG 的 220 对系统比较，只有 7 对差异被视为超出金标准自身抽样噪声。生产案例的 62 个配置在四周内形成 766,350 个唯一判断；独立评测需要 3,765,643 个判断，重复利用率 79.6%，成本约下降 4.9 倍，作者按其价格估算总成本约 800 美元。最终选择的是 hybrid-emb3-large-256，同时考虑 MAP、延迟和 embedding 成本。

创新、局限与失败条件：核心价值是把相关性判断保存为可增量扩展的评测资产，减少新模型加入时的重复劳动，并显式处理传统 pooling 对新检索行为的偏置。该方法不能可靠区分 nDCG 差小于约 0.001 的近乎并列系统；主要判断来自单一 GPT-4.1，跨 judge 的验证只覆盖一套数据。LLM qrels 对绝对分数存在校准偏差，生产案例也没有把检索排名直接等同于最终回答质量；结论依赖固定 judge 版本、query 分布与可复现的文档快照。

适合谁读：RAG 评测、搜索基础设施和模型选型团队。建议优先读 §3 的 pooling 定义与成本分析、§4.3 的 judge 稳定性、§5 的排名/成本结果、§7 的生产案例和 §10 的限制。

4. DocuSearch：企业 RAG 的增益来自“检索后验证”

论文：Hybrid Retrieval-Augmented Generation with Knowledge Graph Expansion, RRF Fusion, and Per-Chunk Grounded Evaluation for Enterprise Document Search（arXiv:2609.01617）
作者：Harish Saragadam、Sudhanshu Sharma、Meghana Pujari
来源/分类：arXiv · cs.IR、cs.AI、cs.LG
全文状态：已核阅公开 PDF（7 页）

核心问题：电信运维文档同时包含术语、缩写、跨段落流程和多厂商边界，单一向量检索容易漏掉词法或结构相关证据；即使召回正确，单段上下文也可能不足以支持生成答案。论文把“召回更多”和“不要无依据回答”作为两个分开的工程目标。

方法与基线：DocuSearch 并行运行 BGE-Large 向量检索、SQLite FTS5 的 BM25 和知识图谱邻居扩展，以 RRF 融合（权重 0.50/0.35/0.15，平滑常数 60），再做 cross-encoder 重排与 MMR 选择。每个候选 chunk 依次经过上下文需求、充分性、回答生成和 groundedness 检查，不通过则取邻居或走多 chunk fallback。评测是生产电信语料上的 120 条人工标注查询，基线为 dense-only 和 dense+BM25；另用 200 条查询测端到端延迟。

作者报告的结果：完整系统 P@10=0.69、R@10=0.79，较 dense-only 的 0.54/0.63 提升 15/16 个百分点。grounding rate 为 89.6%，比 single-pass RAG 的 71.2% 高 18.4 个百分点，幻觉率从 21.4% 降至 6.8%；去掉 groundedness check、充分性评分、邻居扩展、重排或知识图谱都会使 grounding 下降。平均端到端延迟 12.6 秒，其中每 chunk 的评估阶段占 8.4 秒，检索本身低于 1 秒。

创新、局限与失败条件：最值得关注的是把“证据是否足够”和“回答是否被证据支撑”作为生成前的门，而不是只堆更多上下文。样本来自单一企业电信语料，RRF 权重和 chunk 大小是领域内手工设定，跨领域迁移未验证；8.4 秒的串行评估是明显瓶颈，且论文没有给出稳定的公开复现仓库。文中后续关于 RL 自适应检索的性能数字是投影情景，不属于已完成的实证结果。

适合谁读：企业搜索、RAG 可靠性和本地部署工程读者。建议读摘要、§III 的两阶段管线、§V–§VIII 的配置与结果、§IX-A 的限制；不要跳过消融表。

5. SafeEvolve：让安全规则和策略模型共同进化

论文：SafeEvolve: Harness-Policy Co-Evolution from Agent Experience for Safety Alignment（arXiv:2609.02786）
作者：Qinghua Mao、Wanying Qu、Dadi Guo、Leitao Yuan、Qingyu Liu、Yu Li、Guanxu Chen、Yanwei Fu、Xi Lin、Xia Hu、Dongrui Liu
来源/分类：arXiv · cs.AI、cs.CR
全文状态：已核阅公开 PDF（25 页）

核心问题：智能体安全不只由模型参数决定，也取决于 prompt、skills、权限和执行控制组成的 harness。只改 harness 可能超过弱模型的执行能力，只改 policy 又难以适应新风险；论文问能否让两者从已完成的 on-policy 轨迹中持续协同更新。

方法与基线：SafeEvolve 先把轨迹级风险证据归因到单个 harness 组件，做有版本、可回滚的 bounded edit，并用配对 rollout 的门控规则接受更新；再用 harness-use SFT 和 harness-augmented RL 把安全行为内化。作者在 AgentDojo、AgentDyn 的间接提示注入和 AgentHarm 的恶意请求上比较 Base、SFT、DPO、GRPO、MetaSecAlign、AgentAlign 等基线，使用 Qwen3.5-4B 与 Qwen3-4B-Instruct-2507。训练为 200 个 rollout steps，每次更新 256 条轨迹；策略训练用 4 张 H200，评测用 1 张 H200。

作者报告的结果：在 Qwen3.5-4B 上，AgentDojo 的 ASR 从 2.37% 降到 0.79%，正常任务效用从 59.79% 升到 61.86%，AgentHarm harmful score 从 56.45 降到 12.27%，拒答率从 28.98% 升到 83.83%。在较弱的 Qwen3-4B 上，AgentDojo 正常效用从 44.33 升到 60.82%，ASR 从 13.38% 降到 2.42%。留出的 Agent Security Bench 三类攻击中，SafeEvolve 的 ASR 也低于 Base 与 GRPO；但在线 harness 更新会改善部分攻击指标、同时让另一些数据集回归，固定的全局门控比无约束在线更新更稳。

创新、局限与失败条件：贡献是把安全经验外化为可审计、可回滚的运行时工件，再通过 SFT-RL 逐步内化，而不是把所有安全行为压成单一最终回答标签。实验环境主要是 LLM 生成的有限状态 Python 模拟器，风险分布和 4B 骨干不能代表真实 SaaS、多工具权限或开放世界；持续自我改写仍可能出现评估器漂移、奖励投机和跨指标回归。论文报告了 H200 训练配置，但没有给出完整墙钟时间与总成本，复现实验需固定 proposer、verifier 和任务生成版本。

适合谁读：智能体安全、运行时 harness、RL 对齐和红队评测读者。建议优先读 §3 的问题定义与演化算法、§4.1–§4.3 的基线/消融、附录 A.5–A.6 的训练与算力、附录 D 的留出泛化，以及 §5 的限制。代码：SafeEvolve GitHub。
