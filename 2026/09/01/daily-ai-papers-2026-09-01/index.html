Nemotron 3.5：把多模态、多语言和自定义政策塞进 4B 安全审核器

论文：Nemotron 3.5 Content Safety Moderator: A Compact Multimodal, Multilingual, and Reasoning Enabled Content Safety Moderator（arXiv:2608.27548）
作者：Varun Singh、Anuj Doshi、Makesh Narsimhan Sreedhar、Shaona Ghosh、Katherine Luna
来源/分类：arXiv · cs.AI
全文状态：已核阅公开 PDF。

这篇论文问的是：在需要同时理解文本、图片、助手回复、自定义安全政策和多种语言的部署场景中，一个小模型能否替代多套专用 guard。作者以 Gemma 3-4B 为底座做监督微调，输入可以包含用户文本/图片、助手回复和自由文本政策，并通过 /think、/no_think 与 /categories、/no_categories 控制是否输出理由和违规类别。训练混合了真实图片人工标注、多语言文本安全数据、良性文档/图表、罕见风险与越狱合成样本；合成数据经过种子生成、图文对齐、表面多样化、去重、图像/回复生成和人工或三模型多数投票标注，作者还强调人工多模态训练图像中约 99% 是真实照片或纯背景文字。评测覆盖 VLGuard、MM-SafetyBench、Aegis 2.0、XSTest、WildGuard、7 个多语言 benchmark、DynaGuardrail/CoSA，以及 MMMU、DocVQA、AI2D 的良性误杀和 vLLM 延迟。

作者报告的能力面并非全面胜出，而是覆盖面更宽：多模态 prompt harmful-F1 为 0.81，强适用基线 Gemma 3-4B 为 0.68；文本 prompt/response 平均 F1 为 0.85/0.83，低于 Qwen3Guard 的 0.89/0.86；多语言 prompt 为 0.854，接近 Qwen3Guard 的 0.853，response 为 0.847，高于 0.817；自定义政策 prompt 为 0.85，略高于 Granite Guardian 3.3 的 0.83。单张 H100、并发为 1 时，图文 RTVLM 的 TTFT/E2E 为 60/76 ms，Llama Guard 4 为 99/118 ms；DynaGuardrail 文本/政策输入约为 17/33 ms，但开启 reasoning 会增加端到端延迟。创新在于用一个小的视觉语言模型统一输入接口、政策条件和审计理由；但基线是否支持图片、回复分类和自定义政策并不一致，不能把各行数字拼成单一排行榜。

失败条件也很明确：DocVQA 是良性输入误报的主要切片，reasoning 不是所有 benchmark 都改善 F1；训练数据含翻译、合成越狱和模型蒸馏，12 种显式训练语言之外的迁移仍需单独验证。上述数字是作者在公开 benchmark 和单卡环境中的报告，不等于生产流量上的漏报率、漂移稳定性或安全保证。适合做多模态 guard、内容安全平台和推理成本评估的人读，建议优先看接口/分类体系、数据混合与合成管线、表 2 的能力总览、附录 B 的语言/类别切片和附录 D/E 的标注与模板。

Cross-Session Decomposition：安全监测首先是跨会话检索问题

论文：Cross-Session Decomposition Attacks: Scaling Risk and Intent-Aligned Retrieval Defense（arXiv:2608.27945）
作者：Disen Liao、Yihan Wang、Freda Shi、Yaoliang Yu
来源/分类：arXiv · cs.AI
全文状态：已核阅公开 PDF。

论文研究一种单轮监测容易漏掉的攻击：攻击者把一个被禁止的目标拆成多个跨独立会话、单看无害的子问题，再在模型外重组答案。作者先把它形式化为 compositional safety risk，并证明一个有条件的风险转移界：当参考环境已经包含可支持危险重构的分散证据时，部署模型的组合风险与参考组合风险之差受允许子查询上的 excess loss 控制。实验分三层：合成 withholding 试验观察更宽的 Transformer 是否更会从注入事实恢复从未逐字出现的指令；600 个混合领域危险意图的固定 decomposer/composer/judge 评测；以及用留一法检验意图级检索，把每个子查询从库中移除后再找同一隐含意图的其他片段。防御是 22M 参数的 IntentAlign-MiniLM，对比 Jina-v5-small、Harrier、Qwen3-Embedding-0.6B，并接入 Qwen3-4B/8B/14B 和 Llama-3.1-8B guardrail。

作者报告，在 paraphrase-shifted 留出查询上，IntentAlign-MiniLM 的 Recall@10 为 0.649、nDCG@10 为 0.631，高于 Qwen3-Embedding-0.6B 的 0.588/0.558，参数量约少 25 倍。在 K=5 检索片段时，表 3 中对 Qwen3-4B、Qwen3-8B、Qwen3-14B、Llama-3.1-8B 的 harmful recall 分别达到 0.720、0.741、0.585、0.765；K 从 1 增加到 5 会提高所有已测 retriever/guardrail 组合的召回。更大的 Qwen3、Gemma3 家族在固定分解-重组流程中有更高的 harmful-capability uplift，但作者也承认跨模型比较同时改变了训练数据、后训练和拒答政策；Qwen3-14B 的 precision 较高，却可能过于保守而漏掉更多危险意图。价值是把“安全分类”前移成“找回相关历史证据”，并提供了代码仓库；限制是危险意图与重组器仍是受控构造，judge 和 guardrail 的行为会影响结果，真实用户跨会话隐私、保留策略和权限治理没有被实验解决。

适合安全研究、记忆系统、RAG 和 agent 平台工程师阅读，建议先看威胁定义与风险界、600 意图实验，再看留一检索协议、表 2/3 的 paraphrase 结果、50K WildChat 干扰实验和局限。这里的 scaling 结论是作者在合成与跨模型实验中报告的安全风险信号，不是对所有模型规模的因果定律。

Agent 系统的真实成本：同样的完成数，可能相差 19 倍峰值内存

论文：Resource Constraints and Performance in Agentic AI Systems（arXiv:2608.27886）
作者：Amaz Salman、Malka Halgamuge、Teo Susnjak
来源/分类：arXiv · cs.AI
全文状态：已核阅公开 PDF。

这篇论文问的是：完整 agent 系统的任务能力与运行成本是否会一起改善。作者把 OpenClaw 与 NanoBot 当作 model–runtime–tool 整体比较，而不是只测语言模型；两者都使用 gpt-4o-mini，但推理参数、工具环境和运行时不同。主 benchmark 有 100 个共享 prompt，短/中/长任务为 30/35/35，每个系统每题只运行一次；另有 23 个配对且带运行记录的详细子集。作者记录 full/partial/fail 三档结果，并把壁钟时间和容器/运行时峰值内存作为主要操作指标，同时做任务级 bootstrap、McNemar 检验、资源预算曲线和结果-执行 lineage 审计。

100 题主评测的 full completion 为 OpenClaw 31/100、NanoBot 25/100，差异 0.060，95% 任务 bootstrap 区间为 [-0.030, 0.150]，exact McNemar p=0.286，不能据此确立 OpenClaw 的能力优势。23 题详细层中两者都完成 6 题，partial-or-better 为 6/23 对 10/23，p=0.125；但 OpenClaw 的中位壁钟时间为 34.063 秒，NanoBot 为 10.446 秒，几何均值比 2.98（95% 区间 1.78–5.06），峰值内存为 2926.6 MiB 对 136.1 MiB，几何均值比 19.44（95% 区间 17.61–21.32）。OpenClaw 在 23 题中的 19 题更慢、每题记录的峰值内存都更高。作者的核心工程结论是能力、资源和可追溯性应绑定到同一次执行；但这些比较是配置整体的差异，不是某个 harness 组件的因果成本。

创新在于把“完成率”与时间、内存、失败原因和评分来源放在同一张账上；局限同样重要：两个系统的工具和推理设置不相同，23 题子集是有目的抽取而非随机样本，每题只运行一次，评分由单名非盲评估者完成，部分 prompt 还依赖凭证、准备文件或外部服务。部分资源字段来源不完整，论文也没有估计组织生产率、人工监督、维护成本或真实财务回报。因此，这些结果是作者对特定版本和环境的比较报告，不应直接解释为 OpenClaw 架构导致了 19 倍成本。适合 agent infra、评测工程和容量规划读者，建议看表 4 的配置边界、表 5 的结果定义、表 6 的配对结果、资源预算曲线和第 7 节局限。

CareGraph：可审计的健康 AI，最有价值的结果是“拒绝生成”

论文：CareGraph: An Auditable Hybrid AI Framework for Evidence-Grounded Personalized Longitudinal Health Intelligence（arXiv:2608.27484）
作者：Pratik Ghawate、Tanvi Patil
来源/分类：arXiv · cs.AI、cs.IR、cs.MA
全文状态：已核阅公开 PDF。

CareGraph 研究的不是让模型诊断，而是能否把实验性的实验室、病历、自报症状和可穿戴记录整理成趋势、缺失上下文、边界明确的下一步和可追溯解释，同时在证据不充分或输出不安全时阻断发布。架构把确定性数据充分性/趋势规则、场景化缺失上下文检测、患者状态组装、图构建、受约束语言模型综合、证据 key 校验、安全规则和 release gate 分开。开发、验证和替换后的 holdout cohort 各 400 名合成患者，覆盖 8 个场景，每名患者有 3 次年度记录，预计 1,700 个趋势标签；最终还与只接收原始记录和行级 source key 的单体 gpt-5.6 做 56 对匹配比较。

作者报告，冻结的 OLS 趋势规则在 1,700 个 holdout 标签上 accuracy 为 0.827、balanced accuracy 0.846、macro-F1 0.837（95% CI 0.819–0.854），充分性 gate 的 insufficient-data F1 为 0.974；其中 stable 类 F1 只有 0.704，炎症/自身免疫场景 macro-F1 为 0.762，ANA 这一 biomarker 的 macro-F1 仅 0.191。新版缺失上下文检测的 strict precision/recall/micro-F1 为 0.708/0.961/0.815，相比 legacy micro-F1 0.318。作者自制的 39 条安全规则 holdout 上，v1.2 precision 1.000、recall 0.950、F1 0.974，仍有 1 条治疗规划改写漏报。图 provenance 审计覆盖 400 名患者、19,531 个可用 evidence item，source-row recoverability 为 1.000、provenance-complete edge rate 为 0.979；80 人运营审计中完成 79 次 synthesis、78 次 presentation，有一次被阻断、一次因无效 evidence key fail closed。56 对单体比较中，CareGraph 40.15 秒对 49.62 秒更快、661 词对 1,163 词更短，但单体基线使用更少 token 且引用了更多原始证据。

真正的创新是把概率生成放在机器可检查的证据合同之后，而不是把“能写出一段像样的健康建议”当作安全。证据限制不能省略：所有核心数据是合成的，安全 benchmark 是项目自制且未独立专家裁决，图审计没有运行 paired graph/no-graph 内容实验，论文明确说尚未证明图会改善生成质量；56 对比较也不是完整的 1,200-run 设计。适合医疗 AI 安全、数据 lineage、临床讨论辅助和 release engineering 读者，建议看 Algorithm 1、独立合成 cohort、趋势/缺失上下文表、安全规则表、图审计和未完成的下一阶段临床评估。

SOPHIAS 是来自马德里自治大学真实课堂的 12 小时多模态数据集，含 65 名本科生/硕士生的 50 次口头展示，其中 46 次个人展示、4 次小组展示；同步八类时间戳流，包括高清摄像头、环境/摄像头音频、眼动、智能手表生理信号、clicker、键盘和鼠标，并附幻灯片、教师/同伴/自评 rubric 和上下文标注。它能支持多模态学习分析、同伴评价和自动反馈研究；数据通过 Science Data Bank 受控访问、需要数据使用协议，代码据摘要称通过 GitHub 提供。限制是单校、样本规模小且权限受控，摘要没有给预测基线或跨课堂结果，因此是数据资源贡献，不是已验证的教学干预效果。

CompareBench：VLM 的视觉比较推理仍会在数数、空间和时间顺序上失败

论文：CompareBench: A Benchmark for Visual Comparison Reasoning in Vision-Language Models（arXiv:2509.22737）
作者：Jie Cai
来源/分类：arXiv · cs.CV、cs.AI
证据状态：仅依据摘要。

作者把视觉比较拆成数量、几何尺寸、空间关系和时间顺序，构建 TallyBench（2,000 张图像）、OmniCaps（716 张图像）和 CompareBench（1,200 个 QA，四类比较子 benchmark），并在统一协议下评估 Anthropic、Google、OpenAI 的 9 个闭源模型 route。摘要称模型总体表现不弱，却持续在 counting、spatial、geometric 和 temporal ordering 上失败，说明单图识别强不代表比较推理可靠。价值是隔离一个容易被总体平均分掩盖的能力轴；限制是闭源 route 难以复现，摘要没有给各模型数值、提示模板、数据污染检查和发布日期后的代码/数据可用性，结论不能外推到所有 VLM。

From Documents to Reasoning：用验证过的合成数据训练金融数值推理

作者：Lokendra Birla、Milind Savagaonkar、Visnu Srinivasan、Sowmya Rasipuram、Shubhashis Sengupta
来源/分类：arXiv · cs.AI
证据状态：仅依据摘要。

论文针对表格、图表和长文本中的金融 QA，先对合成问答做严格相关性/正确性验证，再用 QLoRA 微调小语言模型；同时提出基于算术表达式匹配答案的评估指标，并把表达式语义相似度、该指标和交叉熵组合成改进损失。作者在 ConvFinQA 上报告微调后准确率显著提升。价值是指出 Exact Match 会把单位、格式等表面差异误当成推理失败；但摘要没有给合成数据规模、表达式解析错误、切分、基线数字和成本，也没有证明金融 QA 提升会转成真实财务分析或交易决策质量。

PCFBench：产品碳足迹的逐步错误会在总数里相互抵消

论文：PCFBench: A Diagnostic Benchmark for Product Carbon Footprint Estimation（arXiv:2608.27716）
作者：Krishna Rao、Andrew Dumit、Shaena Ulissi、Jacob Feintzeig、P. James Joyce、Daniel Frank、Steven Watson、Jonathan Glidden、Gizem Ilayda Dinc、Travis M. Kwee
来源/分类：arXiv · cs.AI
证据状态：仅依据摘要。

PCFBench 把产品碳足迹估算拆成 decomposition、retrieval、ontology matching 和 numerical extraction 等六个独立可评估任务，含 614 个专家标注 item，覆盖不充分描述、冲突上下文和数值约束。摘要报告八个、四家提供方的 frontier LLM 没有单一模型全面领先；最强模型把总产品排放估在申报总量 2 倍以内的比例为 77%，但逐步生成时降到 37%–58%，遵守质量守恒的比例仅 45%–75%。它的贡献是避免只看总数而看不到中间错误；限制是摘要没有给专家一致性、声明值来源、提示/工具条件和真实企业验证，基准分数也不是碳核算合规或减排成效。

Order Matters：中文多面板 meme 的顺序敏感推理

论文：Order Matters: A Chinese Multi-Panel Meme Benchmark for Vision-Language Reasoning（arXiv:2608.26866）
作者：Haihan Li、Haihao Li、Zhenfei Xu、Jize Qian、Yubo Xie
来源/分类：arXiv · cs.CV
证据状态：仅依据摘要。

CMPM 含 1,214 个中文多面板 meme 标注样本，覆盖五种结构类型、顺序依赖、面板顺序约束和可选评论上下文；Task 1 测结构分类与顺序敏感的面板排序，Task 2 用人工 1–3 Likert 评分评估解释中的视觉、面板、幽默、上下文和忠实度。作者在统一协议下比较五个 LVLM，发现正常展示下的准确率不能证明模型理解顺序，打乱面板会明显掉分；Gemini 3.1 Pro 和 GPT-5.5 的解释偏好高于开源模型，评论上下文对 Core4 的增益小且混合。价值是把“看见每一格”与“按叙事顺序组合”分开；限制是摘要没有给具体准确率、人工评分一致性、数据污染和代码/数据最终发布状态，评论上下文结果也不能视为普遍增强。

APeB：个性化 agent 的瓶颈是不会用历史，而不是不会理解明确请求

论文：APeB: Benchmarking Personalization Ability of Large Language Model Agents（arXiv:2607.03162）
作者：Garry Yang、Zizhe Chen、Xinru Chen、Yongqiang Chen、Jianxiang Wang、Deyu Zou、Linyi Ding、Jialiang Wu、Yunzhong He、Yu Gong、James Cheng、Huaixiao Tou
来源/分类：arXiv · cs.AI、cs.HC
证据状态：仅依据摘要。

APeB 从 action logs 构建个性化商品搜索 testbed，把含糊的原始查询、丰富交互历史和用户实际查看的候选商品配对，用多步 agent workflow 评估模型的意图发现、偏好抽取和候选选择。摘要称模型处理明确查询尚可，但在早期、需要发现意图和偏好的查询上明显困难，rubric 分析把差距主要归因于历史使用无效；简单的 history-aware query-refinement pipeline VQRA 能持续提升。它的价值是把原始用户请求和真实历史纳入 benchmark；限制是摘要没有给日志规模、用户/商品切分、在线转化指标和各模型数字，离线动作日志表现不能直接等同于个性化推荐的长期用户价值。

Securing Multi-Agent GIS Systems：红队与结构化 prompt hardening

论文：Securing Multi-Agent GIS Systems: Risk Evaluation and Prompt Hardening Optimization（arXiv:2606.17092）
作者：Kyle Gao、Pranavi Kotta、Linlin Xu、Jonathan Li、David A. Clausi
来源/分类：arXiv · cs.CR、cs.CL
证据状态：仅依据摘要。

论文在一个商业地理空间合作方的 agentic GIS 系统上做安全评估，同时搭建模块化、基于 state machine 的编排框架；攻击侧使用自适应 attacker LLM，评判侧使用给出二元结果和理由的 deterministic judge，覆盖多轮攻击。缓解方法把 prompt 当作结构化 signature，并注入对抗示例，摘要称能系统性提高韧性而不降低任务性能。价值是把 GIS 的工具调用、空间分析和多 agent 协作放在同一红队流程里；限制是摘要没有给攻击集规模、成功率、judge 可靠性或跨系统复现，商业合作方的接口与数据边界也可能使结果难以公开验证。
