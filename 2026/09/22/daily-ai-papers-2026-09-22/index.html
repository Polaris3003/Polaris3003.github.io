1. MME-Safety：细粒度多模态大模型安全评测基准

  • 作者：Yueming Lyu、Yilian Shi、Haoxiang Tan、Linzhuang Zou、Qihao Wang、Guihua Yu、Jie Qin、Xin Gao、Chenyang Si、Jing Dong、Caifeng Shan
  • 来源：arXiv 摘要页 · PDF · 代码
  • 证据状态：已核阅公开 PDF；数字和结论均是论文报告，尚非独立复核结果。

核心问题。 多模态模型可以把风险藏在图片、文字或二者的组合里，单模态安全集和单一拒答率不容易揭示这种跨模态漏洞。论文要回答的是：风险场景、伤害严重度以及图像和文字的隐蔽性，如何共同影响模型的安全行为。

方法与基线。 MME-Safety 用四维标注描述风险场景、伤害严重度、图像隐蔽性和文字隐蔽性，构建了 3,801 个人工核验的图文对，覆盖 9 类风险；随后用分层指标评价响应可靠性、实际风险暴露和防御行为结构，并对 17 个多模态模型做 zero-shot 比较。论文报告的比较包含 Claude 4 Sonnet、o4-mini、Qwen3-VL 等闭源和开放模型，但没有把这些结果当作统一能力排名。评测还使用 GPT-4o 作为部分判断器，因此判断器偏差与提示设置是重要的测量条件。

论文报告的主要结果。 数据集的平均伤害分数为 5.08，低、中、高伤害样本约占 22.9%、46.2%、30.8%；论文报告的整体安全分数中，Claude4-Sonnet-T 为 86.24，Qwen3-VL-235B 无 CoT 为 85.11，o4-mini 为 84.78。高图像隐蔽性、文字隐蔽性同时较高时，相关性识别率从 93% 降到 50.8%；拒答率与有害率、平均伤害分数分别呈 -0.97 和 -0.73 的相关。论文还观察到，CoT 并不保证更安全，某些设置下反而提高了有害输出率或伤害严重度。

创新、局限与适用边界。 价值在于把“是否拒答”拆成风险暴露和防御结构，适合安全评测与红队设计。局限包括只做 zero-shot、类别仍需扩展、GPT-4o 评判可能有偏差，以及没有给出独立的数据污染审计；因此不能把分数直接解释成生产环境事故概率。建议阅读第 3 节的标注与指标、第 4.2–4.3 节的模型结果和附录 A.1、A.5。对做多模态安全、模型评测和安全对齐的人优先级较高。

2. CRYSTAL：不只看最终答案的透明多模态推理评测

  • 作者：Wayner Barrios、SouYoung Jin
  • 来源：arXiv 摘要页 · PDF · 数据集 · 代码
  • 证据状态：已核阅公开 PDF；基准结果和训练增益均为论文报告。

核心问题。 只比较最终答案会掩盖模型是否找到了正确证据、是否遗漏了关键步骤，以及推理步骤顺序是否混乱。CRYSTAL 将多模态推理轨迹作为可核验对象，试图测量“答对”与“理由足够、顺序正确”之间的差距。

方法与基线。 数据集有 6,372 个实例，参考轨迹来自四个 MLLM 的独立生成、语义聚类和人工质量门；来源包括 MathVision、ScienceQA-IMG、RealWorldQA、MMVP 和 PlotQA。Match F1 用语义相似匹配计算步骤精确率与召回率，Ordered Match F1 再用最长递增子序列惩罚乱序。论文比较 20 个模型，包括 Qwen、InternVL、Gemma、Llama、LLaVA 等开放模型以及 GPT-5、GPT-5-mini、GPT-5.2 Instant、Gemini 2.5 Flash 等商用模型；商用模型没有参与基准构造，但原始数据集的预训练污染仍未被单独排除。

论文报告的主要结果。 GPT-5 的答案准确率为 57.99%、Match F1 为 0.612；GPT-5-mini 的准确率为 55.59%、Match F1 为 0.773，且 Ordered Match F1 为 0.670；Gemini 2.5 Flash 的准确率为 53.95%、Match F1 为 0.673。19/20 个模型的步骤精确率高于召回率，说明模型更像是在挑选足以支撑答案的片段，而不是完整恢复参考轨迹；没有竞争模型能让超过 60% 的匹配步骤保持正确顺序。用 CPR-Curriculum 训练 Qwen2.5-VL-3B 后，论文报告 Match F1 从 0.480 升到 0.633、准确率从 39.85% 升到 47.52%；InternVL3.5-4B 的 Match F1 从 0.432 升到 0.833。训练实验使用 4 张 A100，但论文没有给出完整 GPU 小时和成本。

创新、局限与适用边界。 该工作把推理质量拆成步骤覆盖和顺序，且给出可训练的过程奖励；但参考轨迹可能遗漏同样有效的解法，固定语义编码器和阈值具有领域依赖，Ordered Match F1 也不等于真实因果依赖。增益只在两个较小模型上验证，不能直接外推到更大模型或真实任务。建议阅读第 3 节、第 4.1–4.5 节和第 5 节；做过程监督、可解释评测、视觉推理训练的人适合优先读。

3. EnterpriseVal：企业生成式 AI 的效能、可靠性与价值评估

  • 作者：Abbas Raza Ali、Muhammad Ajmal Siddiqui、Moona Zahid
  • 来源：arXiv 摘要页 · PDF
  • 证据状态：已核阅公开 PDF；银行试点是作者记录的 pilot evidence，不是独立验证。

核心问题。 公共 benchmark 能回答“模型会什么”，却不能直接回答某个冻结的企业工作流是否值得上线。EnterpriseVal 试图把模型、提示、检索、工具、护栏和人工监督一起定义为待评估的社会技术配置，并把质量、可靠性、安全和成本放在同一套决策门槛里。

方法与基线。 框架包含 fidelity、utility、efficiency、reliability、assurance、oversight 六组指标，使用校准后的 LLM-as-judge 加专家评分和 prediction-powered inference，再依据置信区间给出 REJECT、CONDITIONAL、SCALE 三档。银行试点覆盖信用备忘录撰写、流程文档转换和控制评估三个工作流，并比较 Gemini 2.5 与 Llama 4 等配置。论文在背景中讨论了污染等评测问题，但试点没有提供独立的数据污染审计；公开 PDF 也没有给出可复现实验代码或完整的原始数据。

论文报告的主要结果。 信用备忘录试点中，Gemini 的引用精确率为 88%、关键实体覆盖为 99%、综合准确率为 93.5%、幻觉率为 1.6%；Llama 的对应引用精确率为 76%、关键实体覆盖为 96%、准确率为 86%、幻觉率为 3.2%。论文设置的内外层门槛分别要求幻觉率低于 10%/5%，引用精确率高于 75%/80%；流程转换的人工精修时间从估计的每份 27.4 小时降到 2.9 小时，另一个版本为 10.6 小时。作者将这些标为试点记录，但没有记录完整样本量、置信区间、评分者一致性、盲评情况或真实上线后的效率。

创新、局限与适用边界。 这篇论文的贡献更接近部署测量协议，而非新的模型能力。单一银行、少量任务、估计的基线工时、未充分披露的 harness parity、没有重复运行可靠性和已实现业务价值，都限制了外推。建议读第 3–6 节的评估框架与门控算法、第 7.2–7.3 节的试点和第 8–9 节的威胁与局限。企业 AI 负责人、评测工程师和需要把 demo 变成上线决策的人适合阅读。

4. CodeMidas：从源代码规模化构造智能编码强化学习环境

  • 作者：Bowen Ye、Lei Li、Shicheng Li、Zihao Yue、Linghao Zhang、Hanglong Lv、Yuanxin Liu、Wenhan Ma、Hao Tian、Rang Li、Jinhao Dong、Yikai Zhao、Xiangwei Deng、Hailin Zhang、Liang Zhao、Qi Liu、Lingpeng Kong、Tong Yang、Fuli Luo
  • 来源：arXiv 摘要页 · PDF
  • 证据状态：已核阅公开 PDF；训练和外部 benchmark 增益为作者报告，尚无独立复现。

核心问题。 编码 agent 的 RL 需要大量任务和可靠 verifier，而 issue/commit 等开发工件覆盖面有限。CodeMidas 只把已有代码作为任务特定输入，让 agent 探索实现、写出行为规范、生成执行验证的测试，并过滤泄漏和不稳定任务。

方法与基线。 产出的训练集包含 5,545 个任务，来自 3,185 个开源代码库，覆盖 23 种语言和 15 个技术领域。任务通过“两个初始失败、四个参考解通过”的执行一致性检查、泄漏检查、解答审计和多次 rollout 过滤。作者用 GRPO 训练 MiMo-V2.5，并在 CodeMidas Val 和多个外部 benchmark 上比较训练前后；公开 PDF 给出 rollout、batch 和验证设置，但没有完整 GPU 小时或金钱成本。数据来自公开代码，论文虽做了泄漏检查，仍不能据此断言训练集与所有外部评测完全无污染。

论文报告的主要结果。 训练后相对基线，SWE-bench Pro 从 50.3% 到 54.4%，DeepSWE 从 10.0% 到 21.7%，ProgramBench 的 Almost Solved 从 4.5% 到 21.5%，RepoZero C2Rust 从 40.5% 到 51.8%，Terminal-Bench v2.1 从 63.7% 到 72.2%；CodeMidas Val 从约 35.0% 到 44.7%。高质量任务从 1k、3k 增加到 5,545 时，DeepSWE 从 17.57% 增到 21.70%，CodeMidas Val 从 41.30% 增到 44.73%。轨迹分析还显示探索、起草和自验证行为增加，但这些行为变化仍是同一作者实验内的相关证据。

创新、局限与适用边界。 把“代码本身”变成可执行环境，扩大了任务来源，也把 verifier 质量变成流水线的一部分。风险在于源代码分布偏差、测试构造器和训练模型之间的潜在泄漏、只验证 MiMo-V2.5，以及外部 benchmark 的比较是否完全同预算、同解码策略。建议阅读第 3 节、第 4.1–4.2 节、第 5.1–5.2 节和附录 A；适合编码 agent、RL 环境和软件工程评测研究者。

5. PlaceReasoner-Beta：推理驱动的芯片宏单元布局与评测

  • 作者：Qiufeng Li、Chengxuan Wang、Rongqian Chen、Quan Cheng、Yihui Ren、Chia-Tung Ho、David Z. Pan、Tian Lan、Weidong Cao
  • 来源：arXiv 摘要页 · PDF
  • 证据状态：已核阅公开 PDF；结果是 16 个开放设计任务上的作者报告，不等于量产芯片验证。

核心问题。 宏布局通常用 HPWL 等代理目标优化，但代理目标与最终布线时序、DRC 和功耗并不总是一致。PlaceReasoner-Beta 让视觉语言模型规划候选布局，再用几何检查、物理检查和 post-route 优化形成闭环。

方法与基线。 基准包含 8 个 RTL 设计、两个纵横比，共 16 个任务和 401 个宏单元，使用开源 Yosys、OpenROAD、FakeRAM 与 Nangate45 流程。默认使用 Claude-Opus-4.8，并用 Qwen3-VL-8B/30B 做补充；每个设计生成 5 个候选。基线包括 DREAMPlace4.0、RTL-MP、ChiPFormer 和模拟退火，每个设计运行 5 次并报告最佳结果。评测同时看 WNS、TNS、DRC、线长、功耗、面积和运行时间/ token；因此“最佳 5 次”选择本身会影响公平性。

论文报告的主要结果。 在 1:1 任务上，系统在所有 8 个设计中取得 DRC-clean 方法里的最佳时序，TNS 相对四个基线在不超过 1,000 个 DRC 约束下减少 61.2%；2:1 任务的对应数字为 53.0%，并在 8 个任务中的 6 个取得最佳 TNS。1:1 的 8 个任务全部干净，2:1 有 5 个干净、3 个只有 1–2 个违规。80 个候选中有 68 个完成布线、42 个 DRC-clean；候选 TNS 的变异系数为 80.36%。平均每个设计约 733 秒、约 290k tokens，明显高于 RTL-MP 的约 96 秒。

创新、局限与适用边界。 亮点是把模型规划、物理检查和后布线反馈连成闭环，而不是只优化一个代理函数。局限包括 beta 系统仍会越界或重叠、候选高度相关、只用 16 个开放设计、5 次运行取最佳、没有任务专用训练，也不代表先进工艺或量产芯片。报告的 token 成本也不能直接换算为 API 费用。建议读第 2–5.7 节，尤其是第 3、4、5.1、5.5、5.6 节；适合 EDA、LLM agent 和物理验证交叉方向。

  • 简介：提出多阶段、可迭代的知识图谱查询流程，由实体、图顶点和线索查询驱动搜索计划。作者报告在 2WikiMultihopQA 与 MuSiQue 上 LLM-as-a-Judge 平均提升 9%，启用搜索计划增强机制相对关闭提升 18%，并在 MINE-1 上报告 89% 信息保留率。
  • 证据状态：仅依据摘要；结果依赖 LLM-as-a-Judge，未核查检索成本、基线实现和数据污染。

10. MIRAGE：多视角创造性语言模型推理

  • 作者：Arash Lagzian、Srinivas Anumasa、Dianbo Liu
  • 来源：arXiv 摘要页 · PDF
  • 简介：由 Selector 选择代数、概率等概念视角，再由 Reasoner 顺序求解，置信度不足时聚合多视角。摘要称在 GSM8K、MATH500、MMLU-Pro 和 Game-of-24 上持续优于 CoT 与多样提示集成，并以较小推理开销换取提升。
  • 证据状态：仅依据摘要；未核阅全文，缺少具体增益、调用次数和模型规模，不能据此判断成本优势。

11. OpenMAS-GCom：图增强多 agent 系统的诊断基准

  • 作者：Kairui Yang、Xunkai Li、Kaixiang Zhang、Minghao An、Zekai Chen、Yuxuan Ba、Rong-Hua Li
  • 来源：arXiv 摘要页 · PDF
  • 简介：通过固定任务、模型、提示和预算，只改变通信边、专家/批评者、错误中间消息或 worker，诊断图增强多 agent 系统的组件贡献。基准包含 17 个配置、29 个数据集、6 个领域和 400 个复杂任务；摘要报告移除专家通常比移除批评者造成更大损失，但没有给出统一数字。
  • 证据状态：仅依据摘要；未核阅全文，不能判断各配置是否完全等 token 或工具预算。

12. SIRA：通过查询锚定对齐进行推理感知的手术器械分割

  • 作者：Zhibo Zhang、Qijie Wang、Zengqiang Yan
  • 来源：arXiv 摘要页 · PDF · 代码
  • 简介：把手术器械分割改写为带手术上下文的查询条件推理，构造含 41,000 个图文对的 SurgRS，并用 query-anchored dual alignment 对齐查询语义、视觉特征和分割提示。作者报告优于既有推理感知基线，但摘要没有给出指标数值。
  • 证据状态：仅依据摘要；未核阅全文，不能核查数据划分、临床外部验证或公平基线。

13. ODU：多模态交互中的上下文用户需求理解

  • 作者：Qi Chen、Yunfei Chu、Haolin He、Yifan Yang、Zihan Liu、Yuxuan Wang、Ziyang Ma、Ruiyang Xu、Meng Gao、Yinsong Yan、Ling Wang、Hui Wang、Wen Huang、Yiheng Chen、Guanrou Yang、Qiuqiang Kong、Jin Xu、Xie Chen
  • 来源：arXiv 摘要页 · PDF
  • 简介：将“用户是否真的提出需求、需求是什么”从响应质量中单独抽出，覆盖单轮/多轮、视觉、声学和对话上下文，并评测 14 个原生 MLLM。作者报告最强的 Gemini 3.1 Pro 只能恢复 44.7% 的关键信息，14 个模型中有 11 个在非需求场景的误触发率超过 50%。
  • 证据状态：仅依据摘要；未核阅全文，误触发定义、音频噪声和测试集构造仍需查全文。
