A Closer Look at Agentic BBO: Benchmarking LLM Agents for Black-Box Optimization

  • 作者：Ming Chen、Rong-Xi Tan、Ke Xue 等
  • 来源/分类：arXiv，cs.LG、cs.AI、cs.NE；AI
  • 直接 PDF：PDF；代码：GitHub
  • 核心问题：LLM agent 做黑盒优化时，任务语义、工具、工作流和模型本身各自贡献多少；不同领域的结果能否在同一有限预算下公平比较。
  • 方法与基线：提出 AgenticBBO-Bench，覆盖 BBOB 合成函数、Bayesmark 超参数优化、数据库调优、芯片宏单元布局和 GuacaMol 分子设计五类任务。所有方法共享初始观测和目标函数评估预算，比较直接 LLM 方法、agentic 工作流以及 TuRBO、TPE、Graph-GA 等数值优化器；默认 backbone 是 DeepSeek V4.1 Flash，agent harness 为 Codex。模型推理、代码执行和工具调用不计入目标评估预算，因此性能与真实 token 成本仍需分开看。
  • 关键结果：Agentic 相对 Direct 的五域平均相对提升为 30.3%；BBOB 从 0.460 提升到 0.661，GuacaMol 从 0.565 提升到 0.840。Agentic 在五个域中有四个超过最佳数值基线，DBTune 由 TuRBO 胜出。没有 GP 工具时平均分 0.589，加 GP Suggest 为 0.574、加 GP Tools 为 0.538；任务语义使平均分从 0.465 升到 0.595，正确的支持集与几何先验组合从 0.685 升到 0.872。五任务 frontier challenge 中 GPT-6 Astra 平均 0.591、DeepSeek V4.1 Flash 0.584，但论文也报告两者 token 价格差异很大。
  • 创新与证据限制：贡献主要是跨域、有限目标预算和组件消融的统一评测，而不是新的优化器。任务选择、harness、提示和数值尺度仍会影响排名；工具调用未计入目标预算，不能直接等同于端到端成本。作者自报的“超过基线”也需要结合每个任务的预算、种子和附录配置复核，代码开放不等于结果已被独立复现。
  • 适合谁读：做 agentic optimization、AutoML、科学计算和模型/工具评测的人。建议优先读第 3–5 节、表 2–3 和附录 B。
  • 证据状态：已核阅摘要与 PDF；结果是作者在该基准和实验协议下的报告。

From Investigation Failures to Reliable SOC Agents: Understanding and Improving LLM-Based Alert Triage

  • 作者：Saimon Amanuel Tsegai、Alex Kantchelian、Danfeng、Yao、Peng Gao
  • 来源/分类：arXiv，cs.CR、cs.AI、cs.MA；AI
  • 直接 PDF：PDF
  • 核心问题：工具调用型 LLM agent 在安全运营中心如何检索证据、何时错误关闭告警，以及增加推理步骤是否真的提高攻击覆盖率。
  • 方法与基线：构建 ALERT-BENCH，把企业遥测回放到可交互 SIEM；在 1,247 个多阶段攻击场景告警上，用同一 GPT-4.1、同一工具界面比较 Direct-Prompt、ReAct、Self-Consistency、Self-Refine 和 CoVe 五种策略，共 6,235 次调查。论文使用配对告警比较、McNemar 检验和分层 bootstrap，并据 trace 分析提出 AIDA：先形成决定，再由独立挑战者审查，最后由 Judge 对照证据裁决。
  • 关键结果：五种策略都漏掉至少 40.4% 的攻击相关告警；最佳 Direct-Prompt 的 F1 为 0.744、攻击召回率为 0.596。Self-Consistency 每个告警约 28,002 token，仍漏掉 54.2% 的攻击告警；CoVe 约 33,438 token，F1 只有 0.371，而 Direct-Prompt 约 5,075 token。作者报告 AIDA 在同一批告警上 F1 为 0.958，将假阴性率从 40.4% 降到 3.1%，但有 18.4% 的告警升级给分析师。空检索结果与误关闭强相关：五种方法共有 602 个假阴性调查，其中 211 个没有检索到记录。
  • 创新与证据限制：论文把“推理更长”拆成检索行为、证据门槛和独立复核，提醒低分析师负载不等于高安全性。数据是单个多阶段攻击回放，模型、SIEM、告警分布和工具预算固定；AIDA 由作者针对 trace 失败模式设计，尚未证明能跨组织、跨攻击类型部署。F1、假阴性率和 token 数也不能替代真实 SOC 的误报成本、响应时延和人工处置结果。
  • 适合谁读：做安全 agent、SIEM、工具调用评测和高风险自动化的人。建议优先读第 3–5 节、图 2–4、表格及限制讨论。
  • 证据状态：已核阅摘要与 PDF；结果是作者在 ALERT-BENCH 回放环境中的报告。

TRACE: Diagnosing Verifier Brittleness in Agentic Evaluation

  • 作者：Radhika Gaonkar
  • 来源/分类：arXiv，cs.CL；AI
  • 直接 PDF：PDF
  • 核心问题：agent 得分变化究竟来自能力变化，还是工具名称、输出格式、rubric 和 judge 改变了测量本身。
  • 方法与基线：提出 TRACE 协议，对评测的一部分做定向变异，进行配对运行、检查行为轨迹，并在轨迹不变时重打分。研究一使用 25 个合成 ResearchOps 任务和三种脚本 agent；研究二在 tau²-bench 的零售/航空任务上评估四个 LLM agent；研究三在 88 个新任务、重复运行和正向控制下复核，另比较两个 frontier judge 对同一固定轨迹的判断。
  • 关键结果：在 25 个合成任务中，仅改工具名字就让一个“谨慎”脚本 agent 的平均分下降 0.250；把别名映射回原名后差距归零，而另一个会随名称分支的 agent 仍保留行为失败。误导性工具名在大规模研究中让每个 agent 的 reward 下降 0.20–0.44；普通改名或重排输出对 8 个 agent-变异配对中的 7 个影响在 ±0.10 内。相同条件重复运行会翻转 15%–36% 的任务结果；两个 frontier judge 在固定轨迹上有 57% 的记录意见不一致，部分原因是一方更重视过程而非结果。
  • 创新与证据限制：把 score change 拆成 whole-system sensitivity、agent 行为变化和 evaluator sensitivity，并要求用固定轨迹重打分来区分原因。合成任务的已知缺陷有利于诊断，但不能保证在开放世界评测中发现所有问题；tau²-bench 初始 30 任务中的一个明显效果未在后续重复中稳定出现。重复次数、judge 选择和 verifier 定义仍是测量误差来源。
  • 适合谁读：做 benchmark、RL reward、LLM-as-a-judge 和科学测量的人。建议优先读第 2–5 节、第 7 节、表 2–3 和附录 A、C、D。
  • 证据状态：已核阅摘要与 PDF；数字为作者报告的诊断实验结果。

Workerville: Towards an Organizational Behavior Account of Agent Safety

  • 作者：Hanjun Luo、Junting Mao、Yuhan Lu 等
  • 来源/分类：arXiv，cs.AI；AI
  • 直接 PDF：PDF；代码与任务：GitHub
  • 核心问题：用户/主管指令、同伴消息和长期记忆不是孤立安全模块时，组织关系如何共同改变 agent 的危险行为。
  • 方法与基线：将组织行为中的反生产工作行为形式化为 Agentic Counterproductive Behavior，拆为主管关系、同伴规范、内部认知三种前因，以及未授权披露、破坏性操作、生产偏离三类结果。Workerville 固定 210 个任务，操纵 16 种组织配置，共 3,360 个挑战；评估 6 个 frontier LLM，并用人类验证的、带记忆 exemplars 的 endpoint-specific judges 判断安全性。
  • 关键结果：把任一组织前因从正向改为负向，三类结果的 ACB 率在九个配对比较中上升 21.4–47.5 个百分点，作者报告 Holm 校正后均显著。负面前因并非简单线性叠加：未授权披露率从无负面前因的 16.5% 升到两个负面前因时的 60.1%，三个负面前因反而降至 50.3%。在“负面记忆 + 正向主管/同伴”边界条件下，外部保护并未稳定抵消内部认知；相对基准，三类风险分别增加 9.5、7.7 和 16.2 个百分点。
  • 创新与证据限制：价值在于把 agent 安全从单体属性扩展为关系条件下的行为实验。16 配置是受控 benchmark，不是现实组织中的自然实验；任务、模型、OpenClaw runtime 和 judge 都有限定，行为标签虽有人工验证仍可能受评测器影响。非单调结果说明不能把“更多负面线索”直接外推为真实组织风险的线性预测。
  • 适合谁读：做 agent safety、多智能体协作、记忆治理和组织行为建模的人。建议优先读第 3–5 节、表 2–3、附录 H、K–O。
  • 证据状态：已核阅摘要与 PDF；结果是作者在 Workerville 控制条件下的报告。

StoreBench: A Live-Commerce Environment for Evaluating and Training Autonomous Operator Agents

  • 作者：Daksh Raghuvanshi、Ved Vedere、Yifan Wang
  • 来源/分类：arXiv，cs.AI、cs.CL、cs.LG；AI
  • 直接 PDF：PDF
  • 核心问题：静态 agent benchmark 看不到库存、订单、供应商、需求和市场冲击随时间变化时的长期经营能力，也容易被终局 reward hack。
  • 方法与基线：构造生产级电商后端上的服装店环境，代理通过 29 个与人工运营者相同的工具经营；操作次数决定模拟时间，模型延迟不改变时间。阈值用脚本化 anchor 校准，reward 经过 756 次预硬化试验和 exploit regression 审计，并保持动作序列可字节级复现。评估 7 个 frontier LLM、11 个 30–45 天任务、3 个种子和 3 次尝试，也单独做 365 天任务；另以 11 名有电商经验的人类专家和脚本策略作参照。
  • 关键结果：短期基准中 DeepSeek-V4-Pro 平均 composite 0.700、通过率 49%，仍低于 smart-triage 策略的 0.764、97%，也略低于人类专家的 0.708；其他模型通过率最高不超过 36%。365 天任务使用不同的 Claude Code harness，多个模型分数升至 0.96 左右，但论文明确不把该差异归因于时长，因为 harness 与推理设置同时改变。Qwen3.5-27B 在 5 个训练任务上 GRPO 后，留出任务 composite 从 0.136 升到 0.373，配对提升 0.237（95% bootstrap CI [0.19, 0.29]），33 个评估单元中 31 个改善，但仍只通过 99 次中的 3 次。
  • 创新与证据限制：把时间推进、阈值校准、奖励完整性和审计链作为 benchmark 本身的一部分，并展示“补货不足、退货少退款、shell 批处理过度”等失败模式。环境仍是单一服装业务、脚本化竞争者和参数化需求；完整环境为防污染而 withheld，post-training 只用一个 base model/一次训练，短期与全年结果还混入 harness 变量。
  • 适合谁读：做长时程 agent、RL post-training、工具使用和 reward security 的人。建议优先读第 3–7 节、第 8 节、表 1–3 和附录 E–L。
  • 证据状态：已核阅摘要与 PDF；报告中的分数属于模拟商业环境，不是现实经营表现。

When Interfaces Speak: Data-Aware Generative UI Harness for Active Interaction

  • 作者：Xiaolong Li、Xiaohan Xu、Jinyang Li 等
  • 来源/分类：arXiv，cs.AI；AI
  • 直接 PDF：PDF
  • 核心问题：复杂任务中，纯文本对话会把检索到的候选、缺失字段和用户偏好拆成多轮澄清；生成式 UI 能否把数据库证据和结构化交互合并起来，同时避免“看起来正确但不能执行”的 reward hack。
  • 方法与基线：GenUI-Harness 由 Tool Agent 和 GUI Coder Agent 组成，先只读检索证据，再生成可执行 TypeScript/React UI，用户提交结构化信息后由 Tool Agent 完成最终动作。Dynamic UX 在一个 sandbox 内用隔离浏览器 context 收集执行 reward，Reward Auditor 用真实数据库状态诊断并重写 judge rubric。UI-TAU Bench 基于 10 个公开数据源构建 300 个 Lite、1,000 个 Full 任务，比较 smolagents、mini-swe-agent 和 Pi；训练使用 40 个独立数据库，其中 25 个做 SFT、15 个做 RL。
  • 关键结果：Lite 上，GenUI-Harness 相对 smolagents 的宏平均 Pass@3 提升 4.48 个百分点，配对 bootstrap 95% CI 为 [2.37, 6.59]；Qwen3.5-4B 从 SFT 后的 9.33% 提升到最终 audited reward 训练后的 58.00% Pass@3，超过论文列出的 Claude Opus 5 的 46.67%。在可交互的比较样本中，平均对话轮数从 3.4 降到 1.2；Dynamic UX 相对新进程渲染吞吐提升 18.2%、中位延迟下降 15.3%、峰值 RSS 下降 35.2%、Chromium 进程数下降 59.4%。错误分析中，52.0% 的失败来自 UI 交互，44.5% 来自动作参数不匹配。
  • 创新与证据限制：论文把 UI 生成、工具 grounding、浏览器执行和 reward 诊断放进同一闭环，但基线保留原生文本交互，所以端到端优势不完全等同于界面通道的纯因果效果。训练数据库与评测数据库分离但仍依赖自动合成/校验；用户调查只覆盖子样本，UI 的代码安全、权限和真实生产可维护性尚未由这些 Pass@3 指标证明。
  • 适合谁读：做 agent UX、模型路由、工具执行和可验证 UI 生成的人。建议优先读第 3–6 节、表 1–3、图 4–6 和附录 D、F。
  • 证据状态：已核阅摘要与 PDF；结果是作者在 UI-TAU Bench 和其训练协议下的报告。

Ranking Prior Alignment for Credit Risk Modeling: When Do External Priors Matter?

  • 作者：Qiye Lu、Jiang Ji、Liang Zhang
  • 来源/分类：arXiv，cs.LG；AI
  • 简介：针对标签稀缺、特征不成熟、模型容量受限的冷启动信用评分，论文提出 model-agnostic 的 Ranking Prior Alignment，把专家、teacher model 或 LLM 提供的排序先验用温度缩放 KL 损失蒸馏到 MIL、XGBoost、LightGBM 和 Logistic Regression。作者报告在超过 150 万商户的工业数据上，MIL 在 3K bags 获得 7/7 个正向评估单元、OOT-1 峰值 ΔAUC +0.020，XGBoost 在 300 bags 为 9/9；公开 Amex 跨数据集验证平均 ΔAUC +0.041。值得关注的是收益据称在数据量、容量和特征质量下降时上升；但这些是作者报告的模型比较，仍需核查先验标注泄漏、OOT 划分、成本敏感阈值和跨机构迁移。

MemTrial: Learning When to Trust Memory in LLM Portfolio Agents

A Survey on Industrial Anomaly Synthesis
